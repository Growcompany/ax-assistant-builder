# 2026-11-11 거절 판정: 문구를 바꿔 말한 거절을 규칙으로 잡기

M-2 축소판 Task 20의 기록입니다. 바꾼 변수는 **거절 판정 규칙 하나**입니다. 모델, 프롬프트, 검색기, 골든셋은 그대로 두었고 LLM도 다시 실행하지 않았습니다. 이미 저장된 모델 출력 150개(50문항 × 3회 실행)에 옛 판정과 새 판정을 각각 적용해 비교했습니다. 기준선 기록(`2026-11-10-baseline.md`)의 숫자는 고치지 않았습니다.

**2026-11-12 수정.** PR #23 리뷰에서 판정기의 오탐이 발견되어 규칙을 좁혔습니다(아래 "리뷰에서 나온 오탐과 수정" 절). 이 문서의 수치는 모두 **좁힌 규칙**으로 계산한 값이고, 처음 규칙의 값은 그 절에 나란히 적었습니다. 라벨은 바꾸지 않았습니다.

## 요약

- 판정기 `classify_refusal`은 답을 `EXACT`(정해진 문구), `PARAPHRASE`(문구를 바꾼 거절), `NONE` 가운데 하나로 분류합니다. 규칙 기반이라 LLM을 호출하지 않습니다.
- 라벨을 단 출력 150개에서 **정밀도는 1.000(30/30), 재현율은 0.732(30/41)입니다**. 옛 규칙(EXACT만)의 재현율은 0.415(17/41)였습니다.
- **이 정밀도는 실제 출력 150개에 나타난 형태의 문장에만 해당합니다.** 리뷰어가 만든 문장 "자료 [1]에 따르면 미성년자는 가입 대상에 포함되지 않습니다"(정답)를 처음 규칙은 거절로 판정했습니다. fixture에는 이런 형태의 출력이 하나도 없어서 정밀도 1.000으로는 이 오탐이 드러나지 않았습니다. 규칙을 고친 뒤 이 영역은 **합성 문장 41개로만** 확인했습니다.
- 규칙을 다듬는 데 쓴 묶음(100개)의 재현율은 0.821입니다. 규칙을 고치는 데 쓰지 않고 평가에만 쓴 검증 묶음(50개)은 0.538입니다. **검증 묶음에서 PARAPHRASE로 잡은 거절은 0개입니다(바꿔 말한 거절 6개 중 0개).** 검증 묶음에서 잡은 7개는 모두 정해진 문구(EXACT)입니다. 좁힌 규칙은 다듬기 묶음에서 본 표현을 벗어나면 거의 일반화하지 못합니다.
- 범위 밖 6문항을 거절한 수는 2/6 → 6/6, 2/6 → 6/6, 4/6 → 4/6입니다. 실행 3개 각각의 값이고, 세 번째 실행은 달라지지 않았습니다.
- **기존 거절 정확도는 거의 그대로입니다**(0.860 → 0.900, 0.860 → 0.880, 0.900 → 0.900). 이 지표는 `거절했는가 == 범위 밖인가`만 보고 검색 실패를 구분하지 않습니다. 범위 밖 문항에서는 점수가 오르지만, 검색이 근거를 가져오지 못해 모델이 거절한 문항이 새로 오답이 되면서 오른 몫의 일부가 상쇄됩니다.
- 그래서 **근거 기준 거절 지표**를 추가했습니다. 상위 k에 근거가 있으면 답변이, 없으면 거절이 정답인 지표입니다. 새 판정으로 계산하면 0.920, 0.900, 0.800입니다. 세 번째 값이 낮은 것은 판정기가 놓친 거절이 "근거 없이 답함"으로 집계되었기 때문입니다. "근거 없이 답함" 11건의 출력을 읽어 보니 **답을 지어낸 것은 0건**이었습니다(결과 3).
- 근거를 가져왔는데도 거절한 과잉 거절(020, 022, 025 등)은 옛 판정과 새 판정에서 같습니다. 판정이 아니라 모델의 문제입니다.

## 판정 규칙

구현은 `src/axbuilder/generation/refusal.py`에 있습니다. 판정기가 구분하려는 것은 다음과 같습니다. **거절은 "이 질문에 답할 근거가 자료에 없다"는 말이고, 정답은 "자료가 이렇게 말한다"는 말입니다.** 자료가 전하는 내용이 부정문이어도("법인은 가입 대상에 포함되지 않습니다", "면제하는 규정은 없습니다") 정답입니다.

1. **EXACT**: 지금까지 쓰던 규칙 그대로입니다. 공백·따옴표·굵게 표시·인용 표시를 지운 뒤 글자나 숫자가 하나도 남지 않거나, 정해진 문구(`제공된 자료로는 확인할 수 없습니다`)로 시작하면 EXACT입니다.
2. **PARAPHRASE**: 답을 문장 단위로 나눴을 때 **모든 문장이 "없음 서술"** 이고, 첫 문장에 `제공된 자료로는`이 있으면 PARAPHRASE입니다.
3. 그 밖은 모두 **NONE**입니다.

문장 하나가 "없음 서술"이 되려면 아래 다섯 조건을 모두 만족해야 합니다.

| 조건 | 내용 | 왜 |
|---|---|---|
| 끝 서술어가 두 형태 중 하나 | (가) 알 수 없음: 같은 문장에 `제공된 자료로는`이 있고 `확인/답변/판단` + `할 수 없`, `하기 어렵`, 또는 `확인되지 않`으로 끝납니다. (나) 자료에 정보가 없음: 주어가 `정보/내용`이거나 위치를 나타내는 말이 `자료에/문서에`이고, `없`, `포함/명시/언급/기재/확인되어 있지 않`으로 끝납니다 | (가)는 프롬프트의 거절 문구에 대상만 끼워 넣은 형태입니다. "전화로는 본인 여부를 확인할 수 없습니다"처럼 `제공된 자료로는`이 없는 문장은 정답일 수 있습니다. (나)에서 주어를 제한하지 않으면 "법인은 가입 대상에 포함되지 않습니다", "면제하는 규정은 없습니다" 같은 **자료의 내용을 전하는 부정문**도 거절로 판정됩니다 |
| 출처 표지가 없음 | `따르면`, `의하면`, `에서는`, `바로는`이 있으면 없음 서술이 아닙니다 | "자료 [1]에 따르면 …"은 출처를 밝힌 답입니다. 뒤가 부정문이어도 마찬가지입니다 |
| 인용 표시로 끝나지 않음 | 문장 끝에 `[n]`이 붙으면 없음 서술이 아닙니다. 문장 앞이나 가운데의 `[n]`("[1]과 [2]는 …만 다루고 있으며")은 괜찮습니다 | 문장 끝의 인용은 "이 말에 근거가 있다"는 모델의 주장입니다 |
| 숫자가 없음 | 인용 표시를 지운 뒤 숫자가 하나라도 있으면 없음 서술이 아닙니다 | "[1]에는 연체이자율이 연 3%p라고 명시되어 있지만 … 은 언급되지 않았습니다"는 이유를 설명하는 모양새지만, 그 수치가 질문 절반에 대한 답입니다(0119-2 bank-042) |
| 역접 문장이면 앞 절이 자료 설명 | `…지만`, `…으나`, `…하나`로 이어지는 역접 문장이면 그 앞 절이 `제공/명시/언급/다루/정의`로 끝나야 합니다 | "철회는 가능하지만 수수료는 확인할 수 없습니다"는 부분 답변입니다(Review Focus 1) |

- 없음 서술이 아닌 문장이 하나라도 있으면 NONE입니다. "긍정 진술"을 따로 찾지는 않습니다.
- 어간과 명사는 다듬기 묶음의 거절 출력에 실제로 나온 것만 넣었습니다. 검증 묶음을 읽으며 본 표현(`제시되어 있지 않`, `찾을 수 없`, `담고 있지 않`, `근거도 포함되지 않`)은 넣지 않았습니다. 넣으면 검증 묶음이 더 이상 검증 역할을 하지 못합니다.

신호를 하나씩 빼 보았습니다. 대상은 fixture 150개와, 정답으로 판정되어야 하는 합성 문장 41개입니다.

| 규칙 | fixture TP / FP / FN | 재현율 | 합성 문장 오탐 |
|---|---|---|---|
| 좁힌 규칙 전체 | 30 / 0 / 11 | 0.732 | 0/41 |
| 출처 표지 조건을 뺌 | 31 / 0 / 10 | 0.756 | 0/41 |
| 문장 끝 인용 조건을 뺌 | 30 / 0 / 11 | 0.732 | 2/41 |
| "인용이 하나라도 있으면 NONE"으로 바꿈 | 26 / 0 / 15 | 0.634 | 0/41 |

- 문장 끝 인용 조건은 fixture의 재현율을 떨어뜨리지 않으면서 합성 문장의 오탐 2개("제공된 자료로는 수집 항목에 계좌 정보는 포함되지 않습니다 [1].", "제공된 자료로는 전화로 본인 여부를 확인할 수 없습니다 [1].")를 막습니다.
- "인용이 하나라도 있으면 답"이라는 더 강한 신호를 쓰면 거절을 4개 더 놓칩니다. 이 모델은 거절하면서도 무관한 인용을 다는 경우가 많기 때문입니다(기준선 bank-046). 그래서 이 신호는 쓰지 않았습니다.
- 출처 표지 조건 때문에 fixture에서 거절 1개를 놓칩니다. 이 표의 합성 문장에서는 다른 조건들이 이미 오탐을 막고 있어서 차이가 없습니다. 그래도 이 조건은 남겼습니다. 리뷰가 지적한 원인, 즉 "자료에 따르면"과 "자료로는"을 구분하지 못하는 문제를 직접 막는 조건이고, 다른 조건이 느슨해지더라도 지켜야 하는 선이기 때문입니다.

## 리뷰에서 나온 오탐과 수정 (PR #23, B1)

처음 규칙은 "첫 문장에 `자료` 또는 `문서`가 있고, 모든 문장의 끝이 `확인/포함/명시/언급/기재` + 부정, 또는 `정보/내용/규정/근거` + `없`"이면 PARAPHRASE로 판정했습니다. 리뷰어가 만든 아래 문장은 모두 거절로 판정됐고, `answer()`를 거치면 답이 정해진 거절 문구로 바뀌어 사라졌습니다.

| 모델 출력(정답인 경우) | 처음 규칙 | 좁힌 규칙 | 막은 조건 |
|---|---|---|---|
| 제공된 자료 [1]에 따르면 전화로는 본인 여부를 확인할 수 없습니다. | paraphrase | none | 출처 표지, `제공된 자료로는` 없음 |
| 자료 [1]에 따르면 미성년자는 가입 대상에 포함되지 않습니다. | paraphrase | none | 출처 표지, 주어가 정보·내용 아님 |
| 자료에 따르면 이 상품의 가입 대상에 법인은 포함되어 있지 않습니다 [1]. | paraphrase | none | 출처 표지, 문장 끝 인용 |
| 자료 [1]에 따르면 이 경우 수수료를 면제하는 규정은 없습니다. | paraphrase | none | 출처 표지, 주어가 `규정` |
| 제공된 자료에 따르면 별도의 제한 규정은 없습니다 [1]. | paraphrase | none | 출처 표지, 문장 끝 인용 |
| 자료 [2]에 의하면 예금자보호법상 보호 한도에 외화예금 이자는 포함되지 않습니다. | paraphrase | none | 출처 표지 |
| 제공된 자료 [1]의 약관에는 중도해지 수수료가 명시되어 있지 않습니다. | paraphrase | none | `제공된 자료로는` 없음, 주어가 `수수료` |
| 문서에 따르면 은행은 이 경우 답변을 하지 않습니다 [1]. | paraphrase | none | 출처 표지, `답변을 하지 않` 형태를 뺌 |

- **원인.** "첫 문장에 `자료|문서`가 있다"는 조건으로는 "자료에 **따르면**"(출처를 밝힌 답)과 "자료**로는**"(거절)을 구분하지 못했습니다. 또 `포함/명시/확인`, `규정/근거` 같은 어간은 정답의 서술어로도 흔히 쓰입니다.
- **정밀도 1.000이 이것을 드러내지 못한 이유(리뷰어가 지적한 그대로).** fixture에서 거절이 아닌 109개 가운데 "첫 문장이 자료/문서를 가리키고 숫자가 하나도 없는" 출력은 **0개**입니다. 처음 규칙이 위험해지는 영역에 실제 출력이 한 번도 들어오지 않았다는 뜻입니다. **정밀도 1.000(34/34)은 이런 종류의 오탐에 대해 아무것도 알려 주지 않았습니다.** 골든셋에도 정답이 "포함되지 않는다 / 규정이 없다" 형태인 문항이 없습니다. 처음 테스트의 Review Focus 2 문장도 규칙에 걸리지 않는 어간(`중도해지`, `질권설정`, `안내`)과 자료를 가리키지 않는 문장만 골라서 통과하고 있었습니다(리뷰 M1).
- **수정.** 위 "판정 규칙"의 다섯 조건 가운데 출처 표지, 문장 끝 인용, (가)의 `제공된 자료로는` 요구, (나)의 주어 제한을 이번에 더했습니다. 첫 문장 조건도 "자료/문서가 있다"에서 "`제공된 자료로는`이 있다"로 좁혔습니다.
- **테스트.** 리뷰어의 8문장과, 같은 종류의 변형 33개를 NONE 명세로 넣었습니다(`tests/generation/test_refusal.py`의 `REVIEW_B1`, `NEGATIVE_ANSWERS`). 출처 표지 네 가지, 인용이 문장 안이나 끝에 있는 형태, 출처 표지 없이 자료의 내용을 전하는 부정문, `제공된 자료로는`으로 시작하지만 인용을 단 부정문, 첫 문장이 부정문인 두 문장짜리 정답이 들어 있습니다. 처음 규칙은 이 41개 가운데 31개를 거절로 판정했습니다.

수정 전후를 같은 fixture 150개와 같은 라벨로 비교했습니다.

- **남은 경계도 그대로 적습니다.** "제공된 자료로는 전화로 본인 여부를 확인할 수 없습니다."(인용 없음)는 여전히 PARAPHRASE로 판정됩니다. 프롬프트의 거절 문구에 대상만 끼워 넣은 형태와 글자가 같아서 규칙으로는 구분할 수 없습니다. 이 모델은 `제공된 자료로는`을 "자료에 따르면"이라는 뜻으로도 씁니다(0119-2 bank-024의 "제공된 자료로는 … 제한 사항이 명시되어 있습니다"). 그런 문장에 인용이 붙어 있으면 위치가 끝이든 가운데든 답으로 봅니다. 2차 리뷰에서 인용이 문장 가운데 있을 때("제공된 자료 [1]로는 …")도 거절로 판정되는 문제가 나와 고쳤고, 이 수정으로 fixture 150개와 보고서의 판정은 바뀌지 않았습니다. 그래도 남는 형태가 둘 있습니다. 하나는 망설인 뒤 둘째 문장에서 답하는 경우("제공된 자료로는 정확히 확인하기 어렵습니다. 다만 … 포함되지 않습니다.")이고, 다른 하나는 앞 절이 답이고 뒤 절이 "확인할 수 없습니다"로 끝나는 경우입니다. 둘 다 인용이 없으면 거절로 판정됩니다. 이 한계는 테스트 `test_known_limit_same_words_as_the_refusal_template`에 적어 두었습니다. **판정에 쓰는 텍스트.** 스크립트는 보고서에 모델 원문(`raw_answer` 또는 `llm.text`)이 있으면 원문으로 판정합니다. 이 세 보고서의 `answer`는 옛 규칙으로 정규화한 텍스트라서, 정해진 문구로 거절한 경우만 고정 문구로 바뀌어 있습니다. 그래서 원문과 `answer` 중 어느 쪽으로 판정해도 150개 모두 결과가 같습니다(출력의 마지막 줄). Task 20 이후에 만든 보고서는 바꿔 말한 거절도 `answer`에서 고정 문구로 바뀌어 있어서, `answer`로 판정하면 당시의 판정을 그대로 되풀이하게 됩니다. 리랭커 실험의 답변 보고서를 다시 채점하다가 이 문제를 발견해, 원문을 먼저 쓰도록 고쳤습니다.

## 해석

거절 정확도라는 숫자 하나에 세 가지 문제가 섞여 있었습니다. 아래는 이번에 이를 나눠서 본 결과입니다.

1. **판정의 문제였던 것은 문구를 바꾼 거절을 알아보지 못한 점입니다.** 범위 밖 6문항의 거절이 2/6에서 6/6으로 늘었습니다(0110, 기준선). 1304는 4/6 그대로이고, 045와 046을 놓쳤습니다. 범위 밖 출력 18개 가운데 16개를 거절로 판정합니다(옛 규칙은 8개). 화면에 보이는 답도 달라집니다. 판정기가 잡은 거절은 정해진 문구로 바뀌고 인용이 붙지 않습니다(기준선의 046에 붙었던 무관한 인용 2개, 005의 3개). 대신 거절 이유를 설명한 문장도 화면에서 사라집니다. 원문은 `Answer.llm.text`와 보고서의 `raw_answer`에 남습니다. 판정기가 놓친 거절(기준선의 017 등)은 모델이 쓴 문장과 인용이 그대로 화면에 나갑니다.

2. **지표 정의의 문제였던 것은 근거가 없어서 거절한 경우를 오답으로 센 점입니다.** 기존 `refusal_correct`는 "범위 밖이면 거절, 아니면 답변"만 정답으로 봅니다. 검색이 근거를 하나도 가져오지 못한 5문항(005, 006, 010, 017, 029)에서 모델이 "자료에 없다"고 답한 것은 받은 자료 기준으로는 옳은 행동인데도 오답이 됩니다. 옛 판정은 그 거절을 알아보지 못하고 "답한 것"으로 세어서 우연히 정답으로 처리했습니다. 그래서 판정만 고치면(결과 3의 1 → 2번 줄) 범위 밖에서 오른 점수의 일부가 여기서 상쇄됩니다. 기준선에서는 범위 밖이 +4문항, 검색 실패 문항이 -3문항이었습니다. 그 결과 0.860이 0.880이 되었습니다. **예전 0.860에는 방향이 반대인 두 종류의 오류가 서로 상쇄되어 있었습니다.** 근거 기준 지표(3번 줄)는 이 둘을 나눕니다. 검색 실패는 검색 지표(Recall@k)로 보고, 거절 지표는 "받은 자료에 맞게 행동했는가"만 봅니다.

3. **다음은 모델의 문제로 남습니다.**
   - **과잉 거절이 실행마다 2~3건 있습니다**(020, 022, 025, 실행에 따라 024). 답이 든 청크를 받고도 정해진 문구로 거절했습니다. 판정을 바꿔도, 지표를 바꿔도 그대로입니다. 라벨로 보면 0110의 bank-034도 과잉 거절인데, 판정기가 이 거절을 놓쳤습니다. 고쳐야 할 곳은 프롬프트나 모델입니다.
   - **근거 없이 답한 것은 판정기 기준으로 2, 2, 7건이지만, 출력을 읽어 보면 지어낸 답은 0건입니다.** 10건은 판정기가 놓친 거절이고, 1건(1304 bank-010)은 거절한 뒤 인접 정보를 덧붙이면서 자료 하나를 틀리게 옮겼습니다. 이 150개 출력에서 모델은 근거가 없을 때 질문의 답을 지어내지 않았습니다. 다만 150개는 50문항을 3회 실행한 것이고, "답했지만 내용이 틀린" 경우(근거가 있는 문항에서의 오답)는 이 지표가 보지 않습니다.

4. **판정기의 문제로는 재현율과, 확인하지 못한 영역이 남습니다.** 1304에서 근거 기준 지표가 0.800으로 기존 지표(0.900)보다 낮은 것은 놓친 거절 6건 때문입니다. 검증 묶음에서 PARAPHRASE 규칙은 거절을 하나도 잡지 못했습니다. 근거 기준 지표를 쓰려면 판정기의 재현율이 뒷받침되어야 하고, 지금은 `ungrounded_answers`에 걸린 문항을 사람이 읽어야 합니다. 정밀도 쪽은 리뷰에서 오탐이 한 번 나왔습니다. 실제 출력으로 계산한 정밀도가 높더라도, 실제 출력에 나오지 않은 영역은 합성 문장으로만 확인했습니다.

5. **그래서 "거절 정확도가 올랐다"고 한 줄로 쓸 수는 없습니다.** 쓸 수 있는 것은 (가) 범위 밖 거절 n/6, (나) 과잉 거절 n건(변화 없음), (다) 근거 없이 답한 n건과 그 내용입니다. 실행 3개, 50문항 규모에서 한두 문항 차이는 잡음입니다.

## 한계

- **합성 문장으로만 확인한 영역이 있습니다.** "자료가 이렇게 말한다"를 부정문으로 전하는 정답("자료에 따르면 … 포함되지 않습니다", "… 규정은 없습니다")은 fixture 150개에도, 골든셋 50문항에도 없습니다. 이 영역에서 판정기가 답을 지우지 않는다는 근거는 리뷰어와 구현 에이전트가 만든 문장 41개뿐입니다. 만든 문장에는 만든 쪽이 떠올린 형태만 담깁니다. 처음 규칙의 오탐도 그렇게 놓쳤습니다. 실제 모델이 이런 답을 낼 때의 정밀도는 알 수 없습니다.
- **규칙으로는 구분할 수 없는 경계가 남아 있습니다.** "제공된 자료로는 X를 확인할 수 없습니다."(인용 없음)는 거절 문구와 글자가 같아서, 모델이 "자료에 따르면 X를 확인할 수 없다"는 뜻으로 썼더라도 거절로 판정합니다. "제공된 자료로는 … 정보는 포함되지 않습니다."도 마찬가지입니다.
- **규칙은 이 모델, 이 프롬프트, 이 코퍼스의 문구에 맞춰져 있습니다.** `qwen3.5:4b`가 "제공된 자료로는 …"으로 시작해 합니다체로 거절하는 버릇에 기대고 있습니다. 다른 모델(Claude 포함)이나 다른 프롬프트에서는 라벨을 단 출력으로 다시 검증해야 합니다. 같은 모델의 다른 실행에서도 재현율이 0.821에서 0.538로 내려갔고, 그 실행에서는 바꿔 말한 거절을 하나도 잡지 못했습니다.
- **검증 묶음은 약한 검증입니다.** 같은 50문항, 같은 모델, 같은 검색 결과에서 샘플링만 다릅니다. 또 라벨을 달 때 세 실행을 모두 읽었으므로, 규칙을 만든 에이전트가 검증 묶음의 표현을 처음 보는 상태는 아니었습니다. 본 표현을 규칙에 넣지 않았을 뿐입니다.
- **표본이 작습니다.** 판정기가 거절로 본 것은 30개이고, 바꿔 말한 거절은 24개(검증 묶음에는 6개)입니다. 검증 묶음의 재현율 0.538은 13개 중 7개라서, 한 문항이 0.077에 해당합니다.
- **라벨은 에이전트가 달았고 사람 검수는 없습니다.** 애매한 7개는 `docs/eval/refusal-labels.md`의 "확인할 항목"에 있습니다.
- **정밀도를 우선한 대가가 있습니다.** 놓친 거절 11개는 화면에 모델 원문과 인용이 그대로 나갑니다. 답을 지우는 것보다는 덜 나쁜 쪽을 골랐습니다.
- **EXACT 규칙의 알려진 구멍은 그대로입니다.** 정해진 문구로 시작하면 뒤에 무엇이 와도 거절로 판정합니다. 0119-2 bank-020의 모델 원문은 정해진 문구 뒤에 "(참고: [1] '… 실패한 날 이후 직접 입금해도 자동이체 우대 조건의 횟수로 인정하지 않습니다.' …)"라고 정답을 인용해 놓고도 거절했습니다. 옛 규칙과 판정이 같아야 한다는 조건 때문에 건드리지 않았습니다.
- **기존 거절 정확도는 검색 실패를 구분하지 않습니다**(해석 2). `refusal_accuracy`의 정의는 계획대로 두고 `grounded_refusal_accuracy`를 따로 추가했습니다.
- **근거 기준 지표는 라벨에 기대고 있습니다.** "근거가 상위 k에 있다"는 골든셋에 라벨된 근거가 들어왔다는 뜻입니다. 라벨에 없는 청크(대체 근거)로 답할 수 있는 문항은 근거가 없는 것으로 잘못 분류되어, 옳게 답해도 "근거 없이 답함"으로 집계됩니다. Task 19의 원문 대조에서 대체 근거가 지적된 문항(bank-004, 009)이 그런 후보입니다. 이 세 실행에서는 두 문항 모두 라벨된 근거가 상위 5개에 들어와 영향이 없었습니다.
- **"근거 없이 답함"이 곧 틀린 답은 아니고, "근거가 있고 답함"이 곧 맞는 답도 아닙니다.** 이 지표는 거절했는지만 보고 답의 내용은 채점하지 않습니다. 근거 일부만 들어온 문항(041, 042)을 "근거 있음"으로 보는 것도 하나의 선택입니다. 그런 문항에서 빠진 절반을 지어내도 이 지표는 잡지 못합니다.
- **근거 기준 지표는 판정기의 재현율에 민감합니다**(해석 4). 놓친 거절이 근거 없는 문항이면 오답으로, 근거 있는 문항이면 정답으로 집계됩니다.
- **한국어 합니다체 거절만 봅니다.** 반말, 해요체 일부, 영어로 된 거절은 잡지 못합니다.
