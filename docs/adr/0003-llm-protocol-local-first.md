# ADR 0003 — LLM은 프로토콜 하나 뒤에 두고, 기본값은 로컬 모델이다

- 상태: 채택 (M-1, 기록 2026-11-10)
- 근거: 설계 문서 4.1 M8·4.4·5장·6장, 조사 [`docs/research/11`](../research/11-korean-rag-stack-2026.md), 학습 노트 [Task 6](../learning/task-06-llm.md)·[Task 7](../learning/task-07-answer.md)·[Task 10](../learning/task-10-api.md)

## 맥락

- 금융·공공 고객은 폐쇄망을 요구한다. 문서가 회사 밖 API로 나가면 안 되는 경우가 많다. 설계의 실패 조건(4.4)에도 "유료 API 없이는 동작하지 않는 구조"가 있다.
- 사용자는 모델을 **종류별로** 비교해 달라고 했다. Claude Opus·Sonnet·Haiku 5.5와 로컬 qwen3.5 4B·9B를 같은 조건으로 비교하고, 이를 근거로 라우팅 정책을 제안하는 것이 목표다.
- 하드웨어는 RTX 3070 Ti 8GB다. 로컬 LLM은 4B~9B급 4bit가 한계이고, 임베딩 모델(약 2GB)과 GPU를 나눠 쓴다.
- 저장소가 공개라서 모델 라이선스가 중요하다. EXAONE 3.5는 비상업 라이선스다.
- 단위 테스트는 네트워크·GPU 없이 돌아야 한다(CI).

## 결정

- `LLMClient` 프로토콜 하나를 둔다. 메서드는 `generate(system, user, max_tokens) -> LLMResponse` 하나다. `LLMResponse`는 text, model, 입력·출력 토큰, latency_ms, stop_reason을 담는다.
- 구현은 셋이다.
  - `OllamaClient`: 기본값이다. 모델은 `qwen3.5:4b-q4_K_M`(Apache-2.0)이고, `think: false`, `num_ctx` 8192를 준다. VRAM이 24GB 미만이면 Ollama 기본 컨텍스트가 4k라서, 근거 청크 5개가 든 프롬프트가 잘릴 수 있다(첫 실험의 입력은 최대 3,824토큰).
  - `ClaudeClient`: 모델은 `claude-opus-5-5`다. `temperature`·`top_p`·`top_k`는 넣지 않는다(400 오류). 서버측 폴백(`fallbacks="default"`)을 쓰고, 시간 제한은 120초, 재시도는 1번이다.
  - `FakeLLM`: 테스트용이다. 정해진 답을 돌려주고 받은 프롬프트를 기록한다.
- `get_llm(settings)`가 `AXB_LLM_MODE`로 고른다. 기본값은 `local`이다.
- 실패는 모두 `LLMUnavailableError` 하나로 모은다. 메시지에 해결 방법(`ollama serve`, API 키 설정)을 담는다. API는 이것을 503으로 돌려준다.
- 유료 호출은 막아 둔다. 평가 CLI는 `AXB_LLM_MODE=cloud`에서 `--with-llm`을 주면 `--allow-cloud` 없이는 실행을 거부한다.

## 대안

| 대안 | 장점 | 고르지 않은 이유 |
|---|---|---|
| LangChain·LiteLLM 같은 LLM 추상화 | 공급자가 많고 바로 쓸 수 있다 | 필요한 것은 "system + user → text + 토큰"뿐이다. 요청 본문(`think`, `num_ctx`, `fallbacks`)을 직접 통제하기 어렵고, 면접에서 설명할 층이 늘어난다 |
| 클라우드(Claude) 기본 | 품질이 높다 | 비용이 들고 문서가 밖으로 나간다. 키가 없으면 아무것도 돌지 않는다(설계의 실패 조건) |
| EXAONE 3.5 7.8B 기본 | 한국어 성능을 자체 보고했다 | 비상업 라이선스이고, 결과물 소유권이 LG에 있다. 비교군으로만 쓴다 |
| qwen3.5 9B 기본 | 4B보다 품질이 나을 가능성 | 6.6GB라 8GB GPU에서 임베딩 모델과 같이 올리기 빠듯하다. M-2 비교 대상이다 |

## 결과

- **좋아진 점**
  - 단위 테스트는 `FakeLLM`으로 네트워크 없이 돈다. API 키가 없어도 전체 흐름이 돌고, 비용은 0이다.
  - API 계층은 "LLM을 못 씀 → 503" 하나만 처리하면 된다.
  - 모델 비교는 같은 `answer()`에 클라이언트만 바꿔 끼우면 된다.
- **대가: 4B 모델의 품질.** 첫 실험 값이다(hybrid + qwen3.5:4b, 50문항, 한 번 실행, [baseline](../experiments/2026-11-10-baseline.md)).
  - 인용 정밀도는 0.662였다. 같은 설정의 다른 실행에서는 0.707이었다. 샘플링 때문에 실행마다 흔들린다.
  - 범위 밖 6문항 중 4개는 정해진 거절 문구 대신 **바꿔 말해** 거절했다. 지어내지는 않았다.
  - 근거를 가져왔는데 거절한 문항이 3/39다.
  - 표의 행을 잘못 읽은 오답도 있다. 든든 정기예금 12개월 기본금리를 2.55%로 답했다. 정답은 2.80%다([Task 7](../learning/task-07-answer.md)).
  - 답변 지연 중앙값은 4,358.52 ms였다. 몇 문항은 20~69 s 걸렸다. 임베딩 모델과 GPU를 같이 써서 생긴 지연으로 추정하며, 확인하지는 않았다.
- **아직 확인하지 않은 것**
  - Claude로는 비용 때문에 평가를 아직 한 번도 돌리지 않았다. M-2 모델 비교에서 사용자 승인 후 돌린다.
  - "local 모드에서 외부 호출 0건"은 아직 테스트로 보장하지 않는다(M-5). 예를 들어 임베딩 모델은 첫 실행 때 Hugging Face에서 받는다.

## 면접에서 "왜 이렇게 했냐"고 물으면

> "고객이 금융·공공이라 문서가 밖으로 나가면 안 되는 경우를 기본으로 놓고, 로컬 모델을 기본값으로 했습니다. 그렇다고 클라우드 비교를 포기하지 않으려고 `generate(system, user)` 하나짜리 프로토콜 뒤에 Ollama, Claude, 가짜 LLM을 두었습니다. 테스트는 가짜 LLM으로 네트워크 없이 돕니다. 프레임워크 대신 직접 만든 이유는 필요한 기능이 작고, `think`나 `num_ctx` 같은 요청 값을 직접 통제해야 했기 때문입니다. 대가는 4B 모델의 품질입니다. 첫 실험에서 인용 정밀도 0.662, 문구를 바꾼 거절, 표 행을 잘못 읽은 오답이 나왔습니다. M-2에서 같은 프로토콜로 Claude와 9B를 비교해 질문 난도별 라우팅을 정할 계획입니다."
