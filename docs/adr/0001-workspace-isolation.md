# ADR 0001 — 모든 데이터를 워크스페이스(회사) 폴더 단위로 분리합니다

- 상태: 채택 (M-1, 기록 2026-11-10)
- 근거: 설계 문서 4.1 M1·4.3, 계획 Global Constraints, 학습 노트 [Task 3](../learning/task-03-workspace-corpus.md)·[Task 10](../learning/task-10-api.md)

## 맥락

- 이 플랫폼은 회사마다 전용 어시스턴트를 만듭니다. A사 문서가 B사 검색 결과에 섞이면 안 되고, "우리 데이터를 지워 달라"는 요청이 오면 한 번에 지울 수 있어야 합니다.
- 회원가입·인증·결제를 갖춘 진짜 멀티테넌트 SaaS는 만들지 않습니다(설계 4.3). 목표는 **데이터와 설정의 분리**까지입니다.
- 원문과 색인은 저작권과 용량 문제로 git에 올리지 않습니다. 올리면 안 되는 경로가 한곳에 모여 있어야 실수가 줄어듭니다.
- 개발은 Docker 없이 PC 한 대에서 하고, 벡터 DB는 Qdrant 로컬(파일) 모드를 씁니다.

## 결정

- 모든 데이터는 `data/workspaces/{id}/` 아래에 둡니다.
  - `workspace.yaml`: 이름, 산업, 역할 → 볼 수 있는 문서 등급(`public`/`internal`)
  - `raw/`: 다운로드 스크립트가 받은 원문, `documents/`: API로 올린 문서
  - `index/`: Qdrant 로컬 저장소와 `index.json`(임베딩 모델·차원·청크 수)
- id는 `^[a-z0-9-]{2,32}$` 형식이어야 하고, Windows 장치 이름(`con`, `nul` 등)은 쓸 수 없습니다. `WorkspaceStore.path()`는 id를 **먼저 검사한 뒤에만** 경로를 만듭니다. `../etc`를 넣으면 `ValueError`가 나고, API에서는 404를 돌려줍니다.
- 색인도 워크스페이스마다 따로 만듭니다. API는 워크스페이스마다 색인 캐시와 잠금을 하나씩 둡니다.
- 워크스페이스 안의 권한은 "역할 → 문서 등급"으로 정합니다. 권한 필터는 생성 단계가 아니라 **검색 단계**에서 겁니다.
- `.gitignore`에 `**/data/workspaces/`를 넣습니다. 그래서 하위 폴더에서 실행해도 원문이 올라가지 않습니다.

## 대안

| 대안 | 장점 | 고르지 않은 이유 |
|---|---|---|
| 컬렉션 하나에 모든 회사 청크를 넣고 `workspace_id`로 필터 | 색인이 하나라 구현이 단순합니다 | 필터를 한 곳에서라도 빠뜨리면 다른 회사 문서가 검색됩니다(fail-open). 회사 하나를 지우거나 백업하려면 쿼리를 따로 짜야 합니다 |
| DB 기반 멀티테넌트 + 인증 | 실제 SaaS에 가깝습니다 | 설계에서 하지 않기로 한 것(Non-goal)입니다. 계정·인증 작업이 이 프로젝트의 핵심인 검색·평가보다 커집니다 |
| 회사마다 프로세스나 컨테이너 | 격리가 가장 강합니다 | 8GB GPU에 임베딩 모델을 여러 번 올리게 됩니다. 배포 단계(M-5)에서 다시 검토합니다 |

## 결과

- **좋아진 점**
  - 폴더 하나가 회사 하나입니다. 삭제·백업·내보내기를 폴더 단위로 끝낼 수 있습니다.
  - 검색기는 해당 워크스페이스 폴더의 색인만 엽니다. 다른 회사 색인을 실수로 검색하는 코드 경로가 없습니다.
  - 경로 조작은 테스트로 고정했습니다(`tests/test_workspace.py::test_rejects_path_traversal_id`).
- **대가**
  - 워크스페이스를 가로지르는 검색은 할 수 없습니다. 의도한 제약입니다.
  - Qdrant 로컬 모드는 한 폴더를 한 프로세스만 열 수 있어서 API 서버를 여러 개 띄울 수 없습니다. M-5에서 Qdrant 서버 모드로 바꿉니다.
  - 역할은 요청 본문이 정합니다. 이것은 **인증이 아닙니다**. 누구나 `준법감시`를 보내면 내부 문서가 담긴 답을 받습니다. 그래서 M-1 서버는 127.0.0.1에서만 띄워야 합니다(`--host 0.0.0.0` 금지). 이것은 운영 규칙일 뿐 코드가 막는 것은 아니고, uvicorn 기본값이 127.0.0.1일 뿐입니다. 토큰 기반 역할은 M-3에서 만듭니다.
  - 골든셋(`corpus/{id}/golden.jsonl`)과 평가 보고서(`reports/{id}/`)도 워크스페이스 id로 나뉩니다. 다만 위치는 `data/` 밖입니다. 골든셋은 커밋하는 파일이기 때문입니다.

## 면접에서 "왜 이렇게 했냐"고 물으면

> "고객사 데이터가 섞이지 않는 것이 이 플랫폼의 최소 조건이라서, 논리 필터 대신 폴더 단위로 물리적으로 나눴습니다. 컬렉션 하나에 회사 id 필터를 거는 방식은 필터를 한 군데서만 빠뜨려도 다른 회사 문서가 검색되는 fail-open 구조입니다. 폴더를 나누면 애초에 다른 회사 색인을 열지 않습니다. id는 정규식으로 검사한 뒤에만 경로로 만들어서 `../` 같은 경로 조작도 막았습니다. 한계는 인증이 아직 없어서 역할을 요청이 정한다는 점이고, M-3에서 토큰 기반으로 바꿀 계획입니다."
