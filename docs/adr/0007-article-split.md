# ADR 0007 — 긴 조항 나누기는 선택 기능으로 두고 기본은 끈다 (켤 때 권장 값 800자)

- 상태: 채택 (Task 26, 기록 2026-11-12)
- 근거: 계획 [M-2 마무리](../superpowers/plans/2026-11-12-m2-rest.md) Task 25·26, 실험 기록 [분할 전후](../experiments/2026-11-12-article-split.md)·[골든셋 v1](../experiments/2026-11-12-golden-v1.md)·[답변 v1](../experiments/2026-11-12-answers-v1.md), 학습 노트 [Task 25](../learning/task-25-article-split.md)

## 맥락

- 리랭커(크로스 인코더)는 (질문, 청크)가 512토큰을 넘으면 뒤를 자른다. 기본 분할은 본문 조항 하나가 청크 하나라, 긴 조항(최대 3,572자)의 뒤쪽 항을 리랭커가 보지 못한다. v0 44문항의 [리랭커 기록](../experiments/2026-11-11-reranker.md)에서 리랭커에 넣은 쌍의 8.7~18.0%가 잘렸고, 답이 잘린 뒤쪽에 있던 네 문항(005, 012, 042, 044)은 적어도 한 리랭커에서 순위가 내려가거나 5위 밖으로 밀렸다.
- Task 25에서 긴 본문 조항을 항 → 호 → 목 → 줄 → 글자 수 순서로 나누는 선택 기능을 넣었다. 서버는 `AXB_MAX_CHUNK_CHARS`, 평가 CLI는 `--max-chunk-chars`다. 토크나이저로 재서 800자를 골랐다(조각의 98% 이상이 512토큰 안). 기본값은 실험 뒤에 정하기로 했다.
- 분할 설정이 바뀌면 이미 만든 색인은 `stale`이 되고 질문은 409다(다시 색인해야 한다).
- 기본 리랭커는 꺼져 있다([ADR 0006](0006-reranker.md)).

## 결정

1. **기본은 나누지 않음**(`AXB_MAX_CHUNK_CHARS`를 비워 둠)으로 유지한다.
2. **선택 기능으로 남긴다.** 켤 때 권장 값은 800이다.

## 근거 (골든셋 v1, 근거가 있는 127문항, k = 5, 답 문구 기준)

| | 기본 | 800자 |
|---|---|---|
| 청크 | 945 | 1,079 (본문 조항 79개 → 213조각) |
| 잘린 쌍, hybrid + KURE 후보 30 | 381 / 3,810 (10.0%) | 10 / 3,810 (0.3%) |
| hybrid R@5 / MRR | 0.870 / 0.752 | 0.870 / 0.737 |
| hybrid + KURE R@5 / MRR | 0.941 / 0.866 | 0.945 / 0.873 |
| 문항 단위, hybrid (새로 맞힘 / 새로 놓침) | | 3 / 3, p = 1.0 |
| 문항 단위, hybrid + KURE | | 1 / 0 (bank-042), p = 1.0 |
| 상위 5개를 같은 조항 조각 2개 이상이 차지한 문항, hybrid + KURE | 0 | 25 / 127 (34칸) |
| 답변 근거 기준 거절 정확도, hybrid + KURE 두 번 | 0.900 · 0.880 | 0.880 · 0.893 |
| LLM 입력 토큰 평균 / 질문당 지연 평균 | 1,984 / 3.19 · 3.18초 | 1,798 / 2.80 · 2.94초 |

- 세 검색기 모두 같은 모양이다. 리랭커와 함께면 새로 맞힘 1 / 새로 놓침 0(bank-042), 리랭커 없이 1~3 / 2~3이고 모두 p = 1.0이다.
- 잘림은 거의 없앴는데 지표가 거의 움직이지 않은 이유는 [분할 기록](../experiments/2026-11-12-article-split.md)에 데이터로 적었다. 나뉜 조항이 근거인 문항이 22 / 127이고, 그중 답이 잘렸을 것으로 추정되는 10문항 중 8개는 나누기 전에도 리랭커가 잘린 앞부분만 보고 5위 안에 넣었으며, 나누어서 생긴 이득은 Recall이 아니라 순위(10문항 중 4개가 한 계단 위로, 1개가 아래로)에 나타났다.

**기본으로 켜지 않는 이유**

- **효과가 한 문항이다.** 리랭커와 함께 켜도 새로 맞힌 문항은 bank-042 하나다.
- **기본 설정(리랭커 꺼짐)에서는 손해다.** 답 문구 기준 MRR이 hybrid 0.752 → 0.737, BM25 0.665 → 0.640, dense 0.810 → 0.801로 내려간다. 같은 조항에서 답 문구가 없는 조각이 답이 든 조각보다 위에 온다. 라벨 기준(hybrid 0.847 → 0.854)만 보면 보이지 않는 손해다.
- **기본값을 바꾸면 이미 색인한 워크스페이스가 모두 `stale`이 되어 다시 색인해야 한다.** 한 문항 이득으로 치르기에는 크다.
- **같은 조항의 조각이 상위 칸을 나눠 갖는다.** 800자에서 21~27문항, 상위 5칸의 4~6%다.

## 대안

| 대안 | 장점 | 고르지 않은 이유 |
|---|---|---|
| 기본으로 켠다 | 잘린 쌍 0.3%, 리랭커와 함께 MRR이 조금 오름, LLM 입력 −9% | 위 "기본으로 켜지 않는 이유" |
| 기능을 뺀다 | 설정과 색인 상태가 단순해진다 | 리랭커를 켠 조건에서는 손해가 없고 순위·LLM 입력에 작은 이득이 있다. 꺼 둔 비용은 설정 한 줄이다 |
| 리랭커를 켜면 자동으로 나눈다 | 손해가 없던 조합만 쓰게 된다 | 리랭커 설정이 색인 구성을 바꾸게 되어 두 설정이 얽힌다(리랭커를 켜고 끌 때마다 다시 색인). 이득이 한 문항이다 |
| 조각으로 채점하되 상위 k에는 조항 하나만 남긴다(부모-자식 청크) | 조각이 칸을 나눠 갖지 않고, 리랭커 없는 조건의 손해도 줄 수 있다 | 아직 구현·측정하지 않았다. [분할 기록](../experiments/2026-11-12-article-split.md)의 다음 실험 후보 |
| 나누지 않고 리랭커 입력 길이를 늘린다 | 색인을 바꾸지 않는다 | 재지 않았다 |

## 결과

**얻은 것**

- 켜면 리랭커 입력의 잘린 쌍이 9.7~13.3%에서 0.3~0.5%로 준다. 리랭커와 함께면 답 문구 MRR이 0.005~0.007 오르고 LLM 입력 토큰이 9% 준다.
- 끈 상태(기본)의 청크는 Task 25 전과 바이트까지 같다(Task 25의 테스트로 고정).

**치르는 것**

- 켜면 청크가 134개 늘고(945 → 1,079) 다시 색인해야 한다.
- 리랭커 없이 켜면 답 문구 기준 순위가 내려간다.

**데이터가 이 결정을 지지하지 않는 부분**

1. **리랭커와 함께 켠 조건에서는 손해가 보이지 않았다.** 세 검색기 모두 새로 놓친 문항이 0이고 MRR이 조금 오르며 LLM 입력과 평균 지연(0.25~0.39초)이 줄었다. "기본 꺼짐"은 이 조합이 해로워서가 아니라 기본 리랭커가 꺼져 있고, 이득이 한 문항이며, 다시 색인하는 비용이 있어서다.
2. **답변 지표의 차이는 실행 간 편차 안이다.** 같은 실행 번호끼리 근거 기준 정답이 9 / 12, 9 / 7 바뀌었다. 답변에서 이득도 손해도 보이지 않는다.
3. **"답이 잘렸을 문항" 10개는 글자 위치로 한 추정이다.** 토크나이저로 문항별 잘린 위치를 다시 세지는 않았다.
4. 골든셋은 에이전트가 만들고 다른 에이전트가 대조했다. 사람 검수는 없다(주인이 판단 위임).

## 다시 정할 때

- 리랭커가 기본으로 켜지면 이 기본값도 함께 다시 본다(그 조합에서는 손해가 없었다).
- 같은 조항 조각을 합치는 방법이 생기면 리랭커 없는 조건의 손해를 다시 잰다.
- 긴 조항이 많은 문서(약관 위주)로 만든 워크스페이스에서는 다시 잰다. 이 코퍼스는 나뉜 조항이 근거인 문항이 17%였다.

## 면접에서 "왜 이렇게 했냐"고 물으면

> "리랭커가 512토큰에서 긴 조항의 뒤를 잘라 답을 못 보는 문제가 있어서, 조항을 항 단위로 나누는 기능을 넣고 토크나이저로 재서 800자를 골랐습니다. 켜 보니 잘린 쌍은 10%에서 0.3%로 줄었는데 Recall은 한 문항만 올랐습니다. 문항별로 보니 나뉜 조항이 근거인 문항이 127개 중 22개뿐이었고, 답이 잘렸을 문항 10개 중 8개는 리랭커가 잘린 앞부분만 보고도 이미 맞히고 있었습니다. 반대로 리랭커 없이 나누면 답이 없는 조각이 답 조각보다 위에 와서 순위가 떨어졌는데, 이건 조항 라벨로 채점하면 보이지 않고 답 문구로 채점해야 보였습니다. 기본 리랭커가 꺼져 있고 이득이 한 문항이며 기본값을 바꾸면 모든 워크스페이스를 다시 색인해야 해서, 기본은 끄고 선택 기능으로 남겼습니다. 리랭커와 함께 켰을 때는 손해가 없었다는 것도 함께 기록했습니다."
