# ADR 0006 — 리랭커는 선택 기능으로 넣고 기본은 끈다 (권장: KURE-Reranker-nano, 후보 30개)

- 상태: 채택 (Task 21, 기록 2026-11-12). 기본 검색기(hybrid)는 [ADR 0002](0002-hybrid-rrf.md)의 잠정 결정을 그대로 둔다
- 근거: 계획 [M-2 축소판](../superpowers/plans/2026-11-11-m2-slim.md) Task 21, 실험 기록 [2026-11-11 리랭커 비교](../experiments/2026-11-11-reranker.md), [기준선](../experiments/2026-11-10-baseline.md), [골든셋 대조 뒤의 수치](../experiments/2026-11-11-golden-audit.md), 학습 노트 [Task 21](../learning/task-21-reranker.md)

## 맥락

- 기준선(골든셋 v0, 근거가 있는 44문항, k = 5)에서 검색은 dense 0.886 / 0.880, hybrid 0.864 / 0.824, BM25 0.841 / 0.746이었다(Recall@5 / MRR). 리랭커는 없었다. **기본값인 hybrid가 dense보다 낮았고**, [ADR 0002](0002-hybrid-rrf.md)는 그 기본값을 "잠정"으로 두면서 M-2에서 리랭커를 붙여 다시 보기로 했다.
- 기준선의 대표 실패는 bank-029다. dense가 정답을 1위로 찾았는데 BM25에서 68위라 RRF 합산에서 밀려 hybrid 상위 10개에도 들지 못했다. 리랭커가 이런 "한 검색기만 찾은 정답"을 살리는지가 질문이었다.
- 제약: 대상 환경은 8GB GPU 한 장이다. 임베딩 모델과 로컬 LLM(Ollama)이 이미 그 메모리를 나눠 쓴다. 기본 설치는 큰 모델을 더 받지 않아야 한다(C 드라이브 여유가 적다).
- 표본: 골든셋은 44문항이고 에이전트가 만들고 에이전트가 대조했다. 한 문항이 Recall에서 0.023이다.

## 결정

**1. 리랭커를 선택 기능으로 넣는다. 기본은 꺼짐이다.**

- 서버: 환경 변수 `AXB_RERANKER`(`none` | `kure-nano` | `bge-v2-m3`, 기본 `none`)와 `AXB_RERANK_CANDIDATES`(기본 30). 켜면 워크스페이스 검색기의 앞 N개를 [`RerankRetriever`](../../src/axbuilder/retrieval/rerank.py)가 다시 정렬한다. 권한 필터는 base 검색기 안에서 먼저 걸리고 리랭커는 걸러진 후보의 본문만 받는다.
- 평가 CLI: `python -m axbuilder.eval.run … --reranker kure-nano --candidates 30`. 보고서 `config`에 리랭커, 후보 수, 잘린 쌍 수를 남긴다.
- 모델은 처음 쓸 때 불러온다. 기본 설치와 단위 테스트는 리랭커 모델 없이 돈다.

**2. 권장 설정은 `nlpai-lab/KURE-Reranker-nano`, 후보 30개다.**

| k = 5, 44문항 | Recall@5 | MRR | 조항 단위(25) Recall@5 | 질문당 지연 평균 |
|---|---|---|---|---|
| hybrid (지금 기본값) | 0.864 | 0.824 | 0.800 | 45 ms |
| hybrid + KURE-nano, 후보 30 | 0.943 | 0.887 | 0.920 | 409 ms |
| hybrid + KURE-nano, 후보 50 | 0.966 | 0.910 | 0.960 | 603~684 ms |
| dense | 0.886 | 0.880 | 0.820 | 48 ms |
| dense + KURE-nano, 후보 30 | 0.966 | 0.921 | 0.960 | 403 ms |

- hybrid에 붙이면 새로 맞힌 문항이 4개(bank-010, 017, 029, 041), 새로 놓친 문항이 0개다. 기준선의 대표 실패 bank-029는 정답이 2위로 올라왔다.
- 후보 30을 고른 이유는 지연이다. 후보 50은 지연이 약 1.5배이고, dense에서는 얻는 것이 없었다(k = 5에서 같고 k = 10에서는 한 문항 나빠졌다). hybrid에서는 후보 50이 한 문항(bank-006) 더 맞혔다. 이 점은 "결과"에 적는다.

**3. 기본으로 켜지 않는 이유.**

- **설치 크기.** 켜면 0.6GB를 더 내려받는다. 기본 설치는 계획에 있는 모델만 받는다.
- **8GB GPU에서 함께 돌 때 비용이 크다.** 이번 실험에서 임베딩 모델과 KURE-nano가 함께 잡은 VRAM은 약 5.3GB였다(바탕화면 등 약 0.7GB 포함, 색인 때의 최댓값). 여기에 Ollama가 함께 올라갈 때의 지연과 메모리는 바로 아래 문단에 있다.
- **44문항 근거로 기본 동작을 바꾸기에는 약하다.** hybrid → hybrid + KURE-nano(후보 30)는 새로 맞힘 4 / 새로 놓침 0이고 정확 맥니마 p = 0.125다. 유의하지 않다. 조합 12개 중 좋은 것을 고른 값이라 낙관 편향도 있다.
- 리랭커가 답변 품질(인용 정밀도, 거절)에 주는 영향은 검색 지표만으로 알 수 없다.

**답변 평가와 VRAM 동시 사용 측정(2026-11-12, 실험 기록의 "답변까지 재기").** 임베딩 모델, 리랭커, Ollama(`qwen3.5:4b-q4_K_M`)를 한 GPU(8GB)에 올리고 50문항을 답하게 했다. 세 실행 모두 실패 없이 끝났지만 VRAM은 리랭커 유무와 관계없이 7.9GB에 붙어 있었다. 리랭커를 함께 올린 두 실행에서는 색인 시간이 22초에서 131~133초로 늘었고 질문당 지연이 0.9~1.4초 늘었다. 답변 쪽은 hybrid 기준으로 인용 정밀도가 0.670에서 0.827로, 근거 없이 답한 문항이 5개에서 1개로 바뀌었다(각각 한 번 실행. 좁힌 거절 규칙으로 다시 채점한 값이고, 처음 규칙으로는 0.687과 4개였다). 그래서 리랭커는 켤 가치가 있지만, 8GB에서 세 모델이 함께 돌 때의 비용이 커서 기본으로 켜지는 않는다. GPU 메모리에 여유가 있거나 LLM이 다른 장비에 있으면 켜는 쪽을 권한다.

**4. 기본 검색기(hybrid)는 바꾸지 않는다.**

- 이번 데이터에서도 dense 쪽이 높거나 같았다. 리랭커 없이 dense 0.886 대 hybrid 0.864, KURE-nano 후보 30에서 dense 0.966 대 hybrid 0.943(한 문항, bank-006), 후보 50에서는 둘 다 0.966으로 같아진다(MRR은 dense 0.921, hybrid 0.910).
- 그래도 "잠정"을 유지하는 이유는 [ADR 0002](0002-hybrid-rrf.md)에 적은 것과 같고, 이번 실험으로 풀리지 않았다.
  - **질문이 자연어 위주다.** 골든셋에 조항 번호("제N조")나 정식 상품명으로 묻는 문항이 없다. 낱말을 그대로 맞춰야 하는 질문은 BM25가 강하고 dense가 약한 영역인데 재지 않았다.
  - **차이가 0~1문항이다.** dense + KURE-nano 대 hybrid + KURE-nano(후보 30)는 한쪽만 맞힌 문항이 1 대 0이고 p = 1.0이다.
  - 골든셋은 아직 사람 검수 전이고 150~200문항으로 늘리지 않았다. ADR 0002의 판단 기준("hybrid 계열이 dense 계열보다 낫지 않으면 dense 계열로 바꾼다")은 그 골든셋을 전제로 한다.

**5. bge-reranker-v2-m3는 선택지로 남기되 권장하지 않는다.**

- 정확도가 KURE-nano보다 낫지 않았다. 후보 30에서 Recall@5는 BM25 0.909 대 0.898(bge 쪽이 0.5문항분 높다), dense 0.955 대 0.966, hybrid 0.932 대 0.943이고, MRR은 여섯 쌍 모두 KURE-nano가 높다. 한쪽만 맞힌 문항은 3 대 2 또는 2 대 2다(p = 1.0).
- hybrid에서 원래 맞히던 문항을 놓쳤다(bank-043, 044). KURE-nano는 hybrid에서 새로 놓친 문항이 없다.
- 비용이 크다: 질문당 지연 약 2배(797 ms 대 403 ms), 내려받는 크기 2.29GB 대 0.6GB, dense 위에 더 잡히는 VRAM 약 2.2GB 대 약 0.6GB. 임베딩 모델과 함께 약 6.9GB가 잡혀 8GB GPU에 LLM이 들어갈 자리가 좁다. 후보 50으로 돌린 한 실행에서는 7.9GB까지 오르고 여섯 문항이 2.9~16.3초 걸렸다(원인 미확인).

## 대안

| 대안 | 장점 | 고르지 않은 이유 |
|---|---|---|
| 리랭커를 기본으로 켠다 | 이번 데이터에서 12개 조합 모두 새로 맞힌 문항이 새로 놓친 문항보다 많았다 | 위 3번. 0.6GB 추가 다운로드, 8GB에서 LLM과 함께 돌 때 색인 시간이 6배로 늘어남, 44문항에서 유의하지 않은 차이 |
| 리랭커를 넣지 않는다 | 코드와 의존성이 줄어든다 | bank-029 같은 RRF의 구조적 실패를 푸는 수단이 없어진다. 꺼 둔 상태의 비용은 설정 한 줄이다 |
| 기본 검색기를 dense로 바꾸고 리랭커를 붙인다 | 이번 표의 최고값(0.966 / 0.921)이고 후보 30으로 충분하다 | 위 4번. 차이가 한 문항이고 BM25가 강한 질문 유형을 재지 않았다 |
| 권장 후보 수를 50으로 한다 | hybrid에서 0.943 → 0.966 (bank-006) | 지연 약 1.5배. 한 문항 차이이고, hybrid에서는 RRF 목록 길이도 함께 바뀌어 어느 쪽 효과인지 가르지 못했다 |
| bge-reranker-v2-m3를 권장한다 | k = 10에서 dense + bge 후보 30이 최고값(0.989). KURE-nano가 못 찾는 bank-005, 042를 찾는다 | 위 5번 |
| BM25 + 리랭커 (임베딩 없이) | VRAM 약 1.1GB로 가장 가볍다. Recall@5 0.898 | 정답이 BM25 후보 밖이면 리랭커가 볼 수 없다(bank-006, 029). dense + 리랭커보다 3문항 낮다 |

## 결과

**얻은 것**

- 켜면 이번 골든셋에서 hybrid의 Recall@5가 0.864 → 0.943, 조항 단위 근거 행이 0.800 → 0.920이 된다. 기준선에서 구조적 실패로 적은 bank-029와 bank-017이 풀린다.
- 끈 상태(기본)의 동작과 수치는 기준선과 같다.

**치르는 것**

- 켜면 질문당 검색 지연이 45 ms → 약 410 ms가 된다. 로컬 LLM 답변 시간(기준선 중앙값 3.2~4.4초)의 1/10 정도다.
- 켜면 VRAM이 약 0.6GB 더 잡히고 모델 0.6GB를 내려받는다.
- 512토큰을 넘는 (질문, 청크) 쌍은 뒤가 잘린다. hybrid + KURE-nano 후보 30에서 9.4%다.

**데이터가 이 결정을 지지하지 않는 부분**

숨기지 않고 적는다.

1. **권장 설정(hybrid + KURE-nano, 후보 30)은 이번 표에서 가장 좋은 조합이 아니다.** dense + KURE-nano 후보 30과 hybrid + KURE-nano 후보 50이 한 문항(bank-006) 더 맞힌다. bank-006의 정답은 BM25 104위라 hybrid의 후보 30개에 들지 못했다. 즉 bank-029에서 본 RRF의 약점이 후보 30에서는 다른 문항에 그대로 남아 있다.
2. **기본 검색기를 바꾸지 않는 것은 데이터가 아니라 표본의 한계에 기댄 결정이다.** 리랭커를 붙인 뒤 hybrid가 dense보다 높은 조건은 하나도 없다. 리랭커가 켜진 상태에서 hybrid만 맞힌 문항도 없다. 기준선에서 "hybrid가 dense가 놓친 것을 찾아 준다"는 근거였던 bank-009와 bank-043·044의 절반은 dense + KURE-nano도 찾는다. bank-037에서는 BM25가 넣은 후보를 KURE-nano가 1위에 올려 hybrid의 역순위가 내려갔다. ADR 0002의 판단 기준을 지금 44문항에 그대로 적용하면 dense 계열로 바꾸는 쪽이다. 바꾸지 않은 것은 그 기준이 전제한 골든셋(150~200문항, 사람 검수, 조항 번호·상품명 질의)이 아직 없기 때문이다.
3. **"기본 꺼짐"도 정확도 데이터와는 반대 방향이다.** 리랭커 조합 12개 모두 Recall@5가 올랐다(2.5~4.5문항분). 유의하지 않고(p = 0.063~0.453) 표본이 작다는 것이 켜지 않는 근거이지, 리랭커가 해롭다는 증거가 있는 것은 아니다.
4. **KURE-nano를 고른 근거는 정확도가 아니라 비용이다.** 두 리랭커의 Recall@5 차이는 k = 5에서 여섯 쌍 모두 0.5문항분이고 서로 다른 문항을 놓친다. KURE-nano는 어느 조합에서도 bank-005(금소법 제28조)와 bank-042의 가계대출약관 제7조를 5위 안에 넣지 못했고 bge-v2-m3는 둘 다 넣었다. dense + KURE-nano는 원래 맞히던 bank-042를 새로 놓친다(제7조가 2위 → 10위).
5. **리랭커가 순위를 내린 문항이 있다.** bank-012는 리랭커를 붙인 12개 조합 모두에서 정답이 1위 → 2위가 됐고(같은 구조의 다른 약관 조항이 1위), bank-029는 KURE-nano에서 dense 1위 → 2위가 됐다. 긴 조항의 답이 512토큰 뒤에 있는 네 문항(005, 012, 042, 044)은 모두 적어도 한 리랭커에서 순위가 내려가거나 5위 밖으로 밀렸다.
6. **bank-009의 "새로 맞힘"은 라벨에 달려 있다.** 두 리랭커 모두 상품설명서 청크 4개를 법 조항 위에 뒀다. 상품설명서도 정답으로 보면([대조 기록](../experiments/2026-11-11-golden-audit.md)의 B) dense는 원래 맞힌 문항이고, dense에서 리랭커가 새로 맞힌 문항은 5개가 아니라 4개다.
7. **k = 10에서는 이득이 작다.** dense는 리랭커 없이 Recall@10이 0.955이고 KURE-nano를 붙이면 0.966~0.977이다. 상위 10개를 LLM에 넘길 수 있는 설정이라면 리랭커 없는 dense가 hybrid + KURE-nano 후보 30(0.943)보다 높다.

**다시 정할 때**

- 답변 평가를 조건마다 여러 번 돌려 인용 정밀도의 차이가 실행 간 편차보다 큰지 확인되면 "기본 꺼짐"을 다시 본다.
- 골든셋을 150~200문항(사람 검수, 조항 번호·상품명 질의 포함)으로 늘린 뒤 dense 대 hybrid, 리랭커 유무, 후보 수를 다시 비교한다. 그때 hybrid 계열이 dense 계열보다 낫지 않으면 ADR 0002의 판단 기준대로 기본 검색기를 바꾸고 새 ADR로 대체한다.
- 리랭커 입력에 제목·조항 이름 붙이기, `max_length` 늘리기, 긴 조항 나누기는 [실험 기록](../experiments/2026-11-11-reranker.md)의 "다음 실험 제안"에 있다.

## 면접에서 "왜 이렇게 했냐"고 물으면

> "기준선에서 하이브리드가 dense보다 낮았고, 원인은 한 검색기만 찾은 정답을 RRF가 버리는 구조였습니다. 그래서 리랭커 두 개를 base 세 종, 후보 30·50개로 비교했습니다. 리랭커를 붙이면 하이브리드의 Recall@5가 0.864에서 0.943으로 올랐고 그 구조적 실패 문항도 풀렸습니다. 그런데 44문항에서 새로 맞힌 문항이 넷(Recall로는 3.5문항분)이라 맥니마 검정으로는 유의하지 않았고(p = 0.125), 8GB GPU에서 임베딩 모델·리랭커·LLM을 함께 돌려 보니 실패는 없었지만 색인 시간이 여섯 배로 늘었습니다. 그래서 기본은 끄고 설정 한 줄로 켜는 선택 기능으로 넣었습니다. 모델은 정확도가 아니라 비용으로 골랐습니다. 두 리랭커의 정확도는 반 문항분 차이였고, 작은 모델이 지연 절반, VRAM 4분의 1 수준이었습니다. 문항별로 보니 512토큰에서 잘린 긴 조항의 답을 리랭커가 못 보는 경우가 있었고, dense 쪽이 여전히 하이브리드보다 높거나 같다는 것도 그대로 기록했습니다. 기본 검색기는 조항 번호로 묻는 질문을 넣은 더 큰 골든셋으로 다시 정합니다."

## 갱신 (2026-11-12, 골든셋 v1)

위 본문은 기록 그대로 둔다. 골든셋 v1(근거가 있는 127문항)로 검색을, 150문항 × 조건 3개 × 2회로 답변을 다시 쟀다. → [골든셋 v1 기록](../experiments/2026-11-12-golden-v1.md), [답변 기록](../experiments/2026-11-12-answers-v1.md)

- **결정(세션 주인): 기본은 꺼 둔 채 유지한다. README에서 "GPU가 있으면 켜는 것을 권장"으로 올린다.** 권장 설정(KURE-Reranker-nano, 후보 30)은 그대로다.
- **검색: 44문항에서 유의하지 않던 이득이 127문항에서 유의해졌다.** k = 5, 답 문구 기준 새로 맞힘 / 새로 놓침이 BM25 15 / 2 (정확 맥니마 p = 0.002), dense 10 / 2 (p = 0.039), hybrid 12 / 2 (p = 0.013)다. 라벨 기준으로는 BM25 12 / 0 (p = 0.0005), hybrid 9 / 1 (p = 0.021)이고 dense는 8 / 2 (p = 0.109)로 유의하지 않다. 같은 보고서에서 v0 44문항 부분만 보면 세 검색기 모두 5 / 1 (p = 0.219)이라, 효과가 새로 생긴 것이 아니라 표본이 커져 알아볼 수 있게 된 것이다.
- **여러 비교를 보정하면 남는 범위가 좁아진다.** Holm 보정으로, 리랭커 비교 3개만 한 묶음이면 답 문구 기준 셋 다 남고, 계획의 비교 11개(리랭커 3, 분할 6, dense 대 hybrid 2)를 한 묶음으로 보면 BM25만 남는다(hybrid 보정 p = 0.129).
- **답변: 거절 쪽은 좋아졌고 인용 정밀도는 그대로다.** hybrid → hybrid + KURE에서 근거 기준 거절 정확도 0.840·0.813 → 0.900·0.880, 근거 없이 답함 11·15 → 6·7, 과잉 거절 13·13 → 9·11이다. 인용 정밀도는 0.760·0.696 → 0.749·0.729로 오르지 않았다. 위 본문의 50문항 한 번 실행에서 본 0.670 → 0.827은 재현되지 않았다.
  - 문항 단위로는 유의하지 않다(같은 실행 번호끼리 근거 기준 정답 20 / 11, p = 0.15; 17 / 7, p = 0.064). 같은 조건을 두 번 돌리면 거절 여부가 14~24문항에서 바뀐다.
  - "근거 없이 답함"의 감소는 주로 검색 실패가 줄어서다(범위 밖이 아닌데 상위 5개에 근거가 없는 문항 9 → 3). 이 지표에 잡힌 50건(준법감시 여섯 실행)을 읽어 보면 47건은 판정기가 놓친 거절이고 실제로 근거 없이 답한 것은 3건이다.
- **비용.** 질문당 검색 지연 hybrid 42 → 400 ms, 답변까지 평균 2.66·2.70 → 3.19·3.18초다. Ollama와 함께 돌 때 VRAM은 리랭커 유무와 상관없이 최대 7.7~7.9GB로 8GB에 붙어 있다. 리랭커 모델을 처음 불러오는 데 BM25 + KURE 실행 기준 10.5~11.3초가 걸렸다.
- **데이터가 이 결정을 지지하지 않는 부분.**
  1. 검색 정확도 데이터는 켜는 쪽이다. 검색기 3 × 분할 2의 여섯 조합 모두 새로 맞힌 문항이 새로 놓친 문항보다 많고(10~17 대 1~2), 리랭커 비교 묶음에서는 보정 뒤에도 유의하다. "기본 꺼짐"은 정확도가 아니라 비용과 환경(0.6GB 내려받기, 처음 쓸 때 모델 불러오기, 8GB GPU에서 LLM과 함께 쓰면 메모리가 참, GPU 없는 PC)에 기댄 결정이다.
  2. 위 본문이 든 비용 중 "LLM과 함께 올리면 색인 시간이 22초에서 131~133초로 는다"는 이번에 재현되지 않았다. 리랭커를 함께 올린 일곱 실행의 색인 시간은 21~39초였다(리랭커 없는 두 실행은 21·28초. 차이의 원인은 확인하지 않았다).
  3. 답변 수준의 이득은 실행 간 편차와 크기가 비슷하고 문항 단위로 유의하지 않다. "켜면 답이 좋아진다"고는 아직 말할 수 없다.
- **다시 정할 때.** 위 본문의 "조건마다 여러 번 돌려 인용 정밀도 차이가 실행 간 편차보다 큰지"는 확인했고, 차이가 편차보다 작았다. 다음은 사람 검수 표본, 거절 판정기를 넓힌 뒤 저장된 출력의 재채점, 상위 10개를 LLM에 넘기는 설정과의 비교다([골든셋 v1 기록](../experiments/2026-11-12-golden-v1.md)의 다음 실험).
