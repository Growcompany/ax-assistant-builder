# 웹 화면(Task 14) 구현 계획

**목표:** `uvicorn axbuilder.api.main:app` 하나로 브라우저에서 워크스페이스 만들기 → 문서 올리기 → 색인 → 역할을 골라 질문 → 인용 원문 확인까지 할 수 있게 한다.

**설계 문서와 다른 점:** 설계 문서는 Streamlit(M-6)이라고 적었다. 사용자가 2026-11-10에 화면을 앞당기라고 했고, Streamlit 대신 FastAPI가 직접 내주는 정적 화면으로 만든다. 이유와 버린 대안은 `docs/adr/0004-web-ui-static.md`에 적는다.

**기준 브랜치:** `task/12-post-release-hardening`(PR #19) 위에 쌓는다(stacked PR). 브랜치 `task/14-web-ui`.

## Global Constraints

- 빌드 도구(Node, 번들러)와 새 파이썬 의존성을 쓰지 않는다. HTML, CSS, 브라우저가 그대로 읽는 ES 모듈 JS만 쓴다.
- 화면은 외부로 요청을 보내지 않는다. CDN, 웹 폰트, 분석 스크립트 금지. 글꼴은 시스템 글꼴(`"Pretendard", "Apple SD Gothic Neo", "Malgun Gothic", system-ui, sans-serif`).
- 정적 파일은 `src/axbuilder/api/static/`에 두고 패키지 데이터로 포함한다(`pip install` 뒤에도 뜬다).
- 문서 제목, 답변, 인용 원문 등 서버에서 온 글자는 모두 `textContent`로만 넣는다. `innerHTML`, `insertAdjacentHTML`, `eval`, 인라인 이벤트 속성 금지.
- 화면 응답에는 `Content-Security-Policy: default-src 'self'; img-src 'self' data:; object-src 'none'; base-uri 'none'; frame-ancestors 'none'`와 `X-Content-Type-Options: nosniff`를 붙인다. 인라인 `<script>`·`<style>`·`style=""`을 쓰지 않는다(CSP가 막는다. 동적 스타일은 클래스나 CSSOM `element.style.setProperty`로).
- 기존 API의 경로, 요청, 응답 필드, 상태 코드는 바꾸지 않는다. 필드 추가만 한다.
- PR #19의 Host·Origin 검사와 `Sec-Fetch-Site` 검사를 그대로 통과해야 한다(같은 출처라 통과한다. 화면을 위해 검사를 느슨하게 하지 않는다).
- 단위 테스트는 네트워크, GPU, 모델, 브라우저 없이 돈다.
- 화면 문구는 한국어.

## Review Focus

1. 문서 제목이나 답변에 `<img onerror=…>` 같은 글자가 있어도 화면에서 실행되지 않는다(글자로 보인다).
2. 조회 API가 권한 밖 정보를 주지 않는다: 인용 원문(`passages`)은 그 질문에서 그 역할로 검색된 청크만 담는다.
3. 색인 뒤에 문서를 올리면 화면이 "색인이 최신이 아님"을 보여 준다(올렸는데 답에 안 나오는 혼란 방지).
4. LLM이 꺼져 있을 때(503) 화면이 멈추지 않고 이유와 해결 방법(Ollama 실행)을 보여 준다.
5. 워크스페이스가 하나도 없는 첫 화면에서 다음에 할 일이 분명하다.

## Task 14-A: 조회 API와 정적 파일 제공 (백엔드)

**Files:** `src/axbuilder/api/app.py`, `tests/api/test_app.py`(또는 새 `tests/api/test_ui_api.py`), `pyproject.toml`(패키지 데이터), `src/axbuilder/api/static/`(이 Task에서는 자리만: `index.html` 최소본)

**Interfaces (Produces)** — 화면(14-B)이 이 모양에 의존한다. 이름과 필드를 바꾸지 않는다.

```
GET /workspaces -> 200 list[WorkspaceSummary]            # id 오름차순
  WorkspaceSummary = {id, name, industry, roles: {역할: [등급]}, documents: int, index: IndexStatus}
  IndexStatus = {state: "none" | "ready" | "stale", chunks: int | null}
    none  = 색인 없음(index.json 없음)
    ready = 색인 있음, 색인 뒤 추가된 문서 없음
    stale = 색인 있음, 색인 뒤 올린 문서가 있음

GET /workspaces/{id} -> 200 WorkspaceDetail | 404
  WorkspaceDetail = WorkspaceSummary + {documents_list: list[DocumentInfo]}   # doc_id 오름차순
  DocumentInfo = {doc_id, title, source, doc_type, access_level, extension, size_bytes, indexed: bool}

POST /workspaces/{id}/ask -> AskResponse (기존) + {passages: list[Passage]}
  Passage = {chunk_id, text}        # citations와 같은 순서, 같은 길이. passages[i]는 citations[i]의 원문

POST /demo-workspace -> 201 {id: "demo", documents: 6} | 409(이미 있음) | 404(저장소의 corpus/bank를 찾지 못함)
  저장소 루트에서 서버를 띄웠을 때 corpus/bank/sources.yaml의 path가 있는 가상 문서 6개로
  워크스페이스 "demo"(이름 "AXB은행(가상)", 역할 상담원=[public], 준법감시=[public, internal])를 만들고 문서를 등록한다.
  색인은 하지 않는다(화면에서 색인 버튼을 누른다). 업로드와 같은 검증·저장 경로를 탄다.

GET /                -> 200 text/html (static/index.html)
GET /static/{path}   -> 정적 파일. 없으면 404
  두 응답 모두 Global Constraints의 CSP·nosniff 헤더를 단다. /docs(Swagger)는 건드리지 않는다.
```

`stale` 판정에 필요한 정보(색인에 들어간 doc_id 목록 등)는 `index/index.json`에 필드를 더해 남긴다. 예전 `index.json`(필드 없음)은 `ready`로 읽지 말고 `stale`로 읽는다(모르면 다시 색인하라고 하는 쪽이 안전).

**테스트(명세):**
- `GET /workspaces`: 빈 목록, 두 개일 때 id순, `documents` 수, `index.state`가 none → ready → (문서 추가 뒤) stale → (재색인 뒤) ready로 바뀐다.
- `GET /workspaces/{id}`: 문서 목록 필드, `indexed`가 색인 전후와 추가 문서에서 맞다. 없는 id 404, 잘못된 id 404.
- `ask`의 `passages`: 길이와 순서가 `citations`와 같고 `chunk_id`가 일치하며 `text`가 그 청크 본문이다. public 역할의 `passages`에 internal 문서 본문이 없다. 거절 응답은 `passages == []`.
- `POST /demo-workspace`: 201 뒤 `GET /workspaces/demo`에 문서 6개(public 3, internal 3), 두 번째는 409, corpus 경로가 없으면 404. 다른 Host·cross-site면 403(기존 미들웨어).
- `GET /`와 `/static/…`: 200, CSP·nosniff 헤더, `/static/../app.py` 같은 경로 조작 404, 다른 Host면 403.
- 설치본에 정적 파일이 포함되는지: `importlib.resources.files("axbuilder.api") / "static" / "index.html"`이 존재.

## Task 14-B: 화면 (프런트엔드)

**Files:** `src/axbuilder/api/static/index.html`, `static/app.css`, `static/js/*.js`(ES 모듈), `static/favicon.svg`

**Consumes:** 14-A의 API와 기존 `POST /workspaces`, `POST /workspaces/{id}/documents`(multipart: `doc_id`, `title`, `source`, `doc_type`, `access_level`, `file`), `POST /workspaces/{id}/index`, `POST /workspaces/{id}/ask`, `GET /health`. 오류는 `{detail: string | list}`.

**화면 구성:**
- **왼쪽 사이드바**: 제품 이름, 워크스페이스 목록(이름, 문서 수, 색인 상태 점), "새 워크스페이스", 맨 아래 서버 상태.
- **첫 화면(워크스페이스 0개)**: 한 문장 소개와 버튼 두 개 — "예시 은행 워크스페이스 불러오기"(`POST /demo-workspace`), "직접 만들기".
- **워크스페이스 화면**: 위에 이름·업종·색인 상태 배지와 "색인 만들기/다시 만들기" 버튼(진행 중 표시, stale이면 강조). 탭 두 개.
  - **질문 탭(기본)**: 역할 선택(그 역할이 볼 수 있는 등급을 함께 표시), 대화 영역, 입력창(Enter 전송, Shift+Enter 줄바꿈). 답변 말풍선 안의 `[n]`은 누를 수 있는 인용 칩. 답변 아래에 인용 카드 목록(문서 제목, 조항, 등급 배지). 칩이나 카드를 누르면 오른쪽 **근거 패널**에 그 청크 원문이 열린다. 거절(`refused=true`)은 다른 색과 "근거 없음 — 답하지 않음" 표시. 응답 시간 표시. 색인이 없으면 입력창 대신 "먼저 색인을 만드세요" 안내. 예시 질문 칩(데모 워크스페이스일 때 README의 질문 4개).
  - **문서 탭**: 문서 표(제목, 형식, 등급, 크기, 색인 여부), 끌어다 놓기 업로드 영역 + 메타 입력(문서 id는 파일 이름에서 자동 제안, 제목, 출처, 문서 종류, 등급은 반드시 직접 고르게), 업로드 결과·오류 표시.
- **새 워크스페이스 대화상자**: id, 이름, 업종, 역할 행(역할 이름 + public/internal 체크) 추가·삭제.
- **공통**: 라이트·다크(시스템 설정 따름 + 전환 버튼, `localStorage`에 저장하되 실패해도 동작), 폭 좁은 화면에서 사이드바 접힘과 근거 패널이 아래로 내려감, 키보드로 모든 동작 가능(포커스 표시, 대화상자 포커스 가둠, `aria-live`로 답변 도착 알림), 오류는 토스트가 아니라 해당 영역 안에 문장으로.

**디자인 방향:** 금융·준법 업무 도구답게 차분하고 밀도 있는 화면. 근거(인용)가 주인공이다 — 답변보다 "어느 문서 몇 조에서 왔는가"가 먼저 눈에 들어와야 한다. 장식용 그러데이션·이모지·둥근 말풍선 일색의 흔한 챗봇 모양을 피한다.

**테스트:** 프런트엔드 단위 테스트 프레임워크는 넣지 않는다. 대신 파이썬 테스트로 정적 검사를 한다(`tests/api/test_static_ui.py`): `static/` 안 모든 파일에 `innerHTML`·`insertAdjacentHTML`·`outerHTML`·`document.write`·`eval(`·`http://`·`https://`(외부 URL)·인라인 `on…=` 속성·`<style`·`style="`이 없다. `index.html`이 참조하는 모든 `/static/…` 경로가 실제로 있다. 실제 동작은 브라우저에서 사람이(세션 주인이) 확인한다.
