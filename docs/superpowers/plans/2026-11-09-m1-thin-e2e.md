# M-1 얇은 전체 버전 (가상 은행) 구현 계획

> **실행 방식 (2026-11-09 변경):** 구현은 **Claude 에이전트 팀**이 한다 (설계 문서 2절). 작업 1개 = 브랜치 1개 = PR 1개, 구현 에이전트와 별도의 리뷰 에이전트가 PR마다 리뷰한다. 작업마다 `docs/learning/task-NN-*.md` 학습 노트를 남긴다. 아래 테스트 코드는 **완료 조건 명세**다. 단계는 체크박스(`- [ ]`)로 진행 상황을 표시한다.

**Goal:** 가상 은행 워크스페이스 1곳에서 "문서 업로드 → 파싱 → 하이브리드 검색 → 인용 달린 답변 → 50문항 평가 → API"가 처음부터 끝까지 돌아가는 첫 버전을 만든다 (12월 지원용).

**Architecture:** 모든 데이터는 워크스페이스 단위로 `data/workspaces/{id}/` 아래에 분리한다. 검색 코어(형태소 BM25, dense, RRF)는 직접 구현하고, LLM은 `LLMClient` 프로토콜 뒤에 로컬(Ollama)과 클라우드(Claude)를 둔다. 테스트는 가짜 임베더·가짜 LLM으로 네트워크 없이 돈다.

**Tech Stack:** Python 3.12+, pydantic v2, kiwipiepy, pdfplumber, PyYAML, sentence-transformers(+PyTorch CUDA), qdrant-client(로컬 모드), anthropic(공식 SDK), httpx, FastAPI, uvicorn, python-multipart, pytest, ruff

**Spec:** `docs/superpowers/specs/2026-11-09-company-assistant-builder-design.md`

## Global Constraints

- Python ≥ 3.11 (`pyproject.toml`). 3.13에서 라이브러리 설치가 실패하면 3.12 가상환경 사용
- 패키지 이름: `axbuilder` (기존 `rag_app`에서 변경), 소스는 `src/axbuilder/`
- 모든 데이터·색인·설정은 `data/workspaces/{workspace_id}/` 아래. 이 경로는 git에 올리지 않음
- 워크스페이스 id 형식: `^[a-z0-9-]{2,32}$`
- 원본 문서(은행 PDF 등)는 커밋 금지. `corpus/{workspace_id}/sources.yaml`(출처 목록)과 다운로드 스크립트만 커밋
- **단위 테스트는 네트워크·GPU·모델 다운로드 없이** 통과해야 함 (CI). 실제 모델을 쓰는 테스트는 `@pytest.mark.slow`로 표시하고 CI에서 제외
- 환경변수: `AXB_DATA_DIR`(기본 `data`), `AXB_LLM_MODE`(`local`|`cloud`, 기본 `local`), `AXB_LOCAL_MODEL`(기본 `qwen3.5:4b-q4_K_M` — Apache-2.0. EXAONE은 비상업 라이선스라 비교군으로만), `AXB_OLLAMA_URL`(기본 `http://localhost:11434`), `AXB_CLAUDE_MODEL`(기본 `claude-opus-5-5`), `AXB_EMBED_MODEL`(기본 `dragonkue/snowflake-arctic-embed-l-v2.0-ko` — 한국어 검색 nDCG@10이 bge-m3보다 높고 크기는 같음. bge-m3는 M-2 비교 기준), `ANTHROPIC_API_KEY`
- Claude 호출에 `temperature`/`top_p`/`top_k`를 넣지 않는다 (현재 API에서 400 오류)
- 거절 문구는 정확히: `제공된 자료로는 확인할 수 없습니다.`
- 코드 스타일: `ruff check .` 와 `ruff format --check .` 통과 (CI가 검사)

## Review Focus

이 계획의 테스트가 직접 다루지 않으면 사용자를 괴롭힐 입력 5가지 — 각각 담당 작업에 테스트를 추가해 두었다.

1. **텍스트가 없는 PDF(스캔본)** → 빈 청크를 색인하지 않고 건너뛴다 (Task 2 `test_empty_document_yields_no_chunks`)
2. **불용어만 있는 짧은 질문** ("은?") → BM25가 오류 없이 빈 결과, 하이브리드는 dense 결과로 동작 (Task 1 `test_query_without_content_tokens`, Task 5 `test_hybrid_works_when_bm25_empty`)
3. **경로를 벗어나는 워크스페이스 id** (`../etc`) → `ValueError` (Task 3 `test_rejects_path_traversal_id`)
4. **LLM이 없는 인용 번호를 출력** (`[9]`) → 무시하고 오류 없이 처리 (Task 7 `test_ignores_out_of_range_citation`)
5. **Ollama가 꺼져 있거나 API 키가 없음** → 원인을 알려주는 `LLMUnavailableError`, API는 503 (Task 6 `test_ollama_unreachable_raises`, Task 10 `test_ask_returns_503_when_llm_down`)

```python
# tests/retrieval/test_bm25.py  (chunk 헬퍼로 Chunk 3개를 만든다)
# c1: "예금자 보호 한도는 1억원이다", c2: "전자금융거래 접근매체 관리", c3: "예금 금리 우대 조건"
def test_ranks_matching_chunk_first():
    idx = BM25Index(); idx.build([c1, c2, c3])
    assert idx.search("예금자 보호 한도", k=3)[0].chunk.chunk_id == c1.chunk_id

def test_rare_term_scores_higher_than_common_term():
    # "예금"은 c1·c3에, "접근매체"는 c2에만 있다
    idx = BM25Index(); idx.build([c1, c2, c3])
    assert idx.search("접근매체", k=1)[0].score > idx.search("예금", k=1)[0].score

def test_no_match_returns_empty():
    idx = BM25Index(); idx.build([c1, c2, c3])
    assert idx.search("자동차보험", k=3) == []

def test_query_without_content_tokens():
    idx = BM25Index(); idx.build([c1, c2, c3])
    assert idx.search("은?", k=3) == []

def test_access_level_filter():
    internal = c3.model_copy(update={"access_level": "internal"})
    idx = BM25Index(); idx.build([c1, c2, internal])
    ids = [r.chunk.chunk_id for r in idx.search("예금", k=3, access_levels=["public"])]
    assert internal.chunk_id not in ids
```

- [ ] **Step 2:** `pytest tests/retrieval -v` → 실패 확인 (import 오류)
- [ ] **Step 3: `tokenize()` 구현** — Kiwi 품사 태그가 `NN`(명사), `VV`(동사), `VA`(형용사), `XR`(어근), `SL`(외국어), `SN`(숫자)으로 시작하는 형태소의 `form`만 남긴다(**접두사 비교** — Kiwi는 `VV-R`, `VV-I`처럼 접미사를 붙인다). Kiwi는 단독으로 온 조사(`은?`의 `은`)를 `NNG`로 볼 수 있으므로 1글자 조사 불용어 집합으로 한 번 더 거른다. `NR`·`NP`·`SH` 포함 여부는 M-2 실험 항목 `Kiwi()` 객체는 모듈에서 한 번만 만든다(생성 비용이 큼)
- [ ] **Step 4: `BM25Index` 구현** — 라이브러리 없이 직접. 점수가 0인 청크는 결과에서 뺀다

```
IDF(q)      = ln( (N - n(q) + 0.5) / (n(q) + 0.5) + 1 )
score(D, Q) = Σ_q IDF(q) · f(q,D)·(k1+1) / ( f(q,D) + k1·(1 - b + b·|D|/avgdl) )
N: 청크 수, n(q): q를 포함한 청크 수, f(q,D): D 안의 q 빈도, |D|: D의 토큰 수, avgdl: 평균 토큰 수
```

### Task 9: 평가 실행기와 첫 수치

**알아야 할 개념:** Recall@k와 MRR이 각각 무엇을 놓치는가, 인용 정밀도, 거절 정확도, 실험 기록 습관

**Files:**
- Create: `src/axbuilder/eval/metrics.py`, `src/axbuilder/eval/run.py`
- Test: `tests/eval/test_metrics.py`, `tests/eval/test_run.py`

**Interfaces:**
- Consumes: `GoldItem`, `Retriever`, `answer()`, `LLMClient`
- Produces:
  - `matches(chunk: Chunk, ev: Evidence) -> bool` — doc_id가 같고, `ev.article`이 있으면 article이 같고, `ev.page`가 있으면 page가 같음
  - `recall_at_k(retrieved: list[Chunk], evidence: list[Evidence], k: int) -> float` — 상위 k개로 맞춘 evidence의 비율
  - `reciprocal_rank(retrieved: list[Chunk], evidence: list[Evidence]) -> float` — 처음 맞는 청크 순위의 역수, 없으면 0
  - `citation_precision(citations: list[Citation], evidence: list[Evidence]) -> float | None` — 인용 중 evidence에 맞는 비율, 인용이 없으면 `None`
  - `refusal_correct(refused: bool, qtype: str) -> bool` — `refused == (qtype == "out_of_scope")`
  - `class EvalReport(BaseModel)`: `config: dict`, `n: int`, `recall_at_k: float`, `mrr: float`, `citation_precision: float | None`, `refusal_accuracy: float | None`, `by_qtype: dict[str, dict[str, float]]`, `items: list[dict]`
  - `run_eval(items: list[GoldItem], retriever: Retriever, k: int, llm: LLMClient | None, workspace: Workspace, role: str) -> EvalReport` — `llm`이 `None`이면 검색 지표만 (`out_of_scope` 문항은 검색 지표 계산에서 제외)
  - CLI: `python -m axbuilder.eval.run --workspace bank --retriever {bm25,dense,hybrid} --k 5 [--with-llm]` → `reports/bank/{YYYYmmdd-HHMM}-{retriever}.json` 저장 + 마크다운 표 출력
