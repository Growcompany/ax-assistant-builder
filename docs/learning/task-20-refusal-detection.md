# Task 20 — 바꿔 말한 거절 판정

## 이 작업이 하는 일

- 문제: `answer()`는 모델의 답이 정해진 문구(`제공된 자료로는 확인할 수 없습니다.`)로 시작할 때만 거절로 봤다. 그런데 작은 모델(qwen3.5:4b)은 "제공된 자료로는 달러 환율을 확인할 수 없습니다."처럼 **문구를 바꿔** 거절한다. 그러면 (1) 평가에서 거절이 답변으로 세어지고(범위 밖 6문항 중 2개만 거절로 잡혀 0.333), (2) 화면에는 거절인데 무관한 인용이 붙어 나간다.
- 한 일:
  - `src/axbuilder/generation/refusal.py`: `classify_refusal(text) -> RefusalKind`. `EXACT`(정해진 문구, 기존 규칙 그대로) / `PARAPHRASE`(문구를 바꾼 거절) / `NONE`(답변, 부분 답변).
  - `answer()`: `PARAPHRASE`도 `EXACT`처럼 `refused=True`, 정해진 문구, 인용 없음으로 정규화한다. 모델이 쓴 원래 문장은 `Answer.llm.text`에 남는다. `Answer.refusal_kind`를 더했다. API 응답 모양은 그대로다.
  - 평가: 문항 기록에 `refusal_kind`, `raw_answer`, 요약에 `refusal_accuracy_strict`(EXACT만 거절로 센 예전 방식)를 더했다.
  - 근거 기준 거절 지표: `metrics.grounded_refusal_correct(refused, evidence_in_context)`와 요약의 `grounded_refusal_accuracy`, `over_refusals`, `grounded_refusals`, `ungrounded_answers`. 검색 실패와 생성 실패를 따로 잰다.
  - `scripts/rescore_refusals.py`: 저장된 보고서를 새 규칙으로 다시 채점해 전후 표를 낸다. 모델을 다시 돌리지 않는다.
  - `tests/fixtures/refusal_outputs.jsonl`: 실제 모델 출력 150개와 정답 라벨. `docs/eval/refusal-labels.md`에 라벨 기준.
- 결과(`docs/experiments/2026-11-11-refusal-detection.md`): 150개에서 정밀도 1.000(30/30), 재현율 0.732(30/41). 범위 밖 거절은 2/6 → 6/6, 2/6 → 6/6, 4/6 → 4/6. 전체 거절 정확도는 거의 그대로(0.860 → 0.900, 0.860 → 0.880, 0.900 → 0.900)다. 이 작업에서 배울 것은 두 가지다: 그 숫자가 왜 안 올랐는가, 그리고 **정밀도 1.000인데 리뷰에서 왜 오탐이 나왔는가**(아래).

## 핵심 개념

**정밀도와 재현율 (거절 클래스 기준)**
- 정밀도 = 판정기가 "거절"이라고 한 것 중 진짜 거절의 비율. 낮으면 **정상 답이 거절 문구로 바뀌어 사라진다.**
- 재현율 = 진짜 거절 중 판정기가 잡은 비율. 낮으면 **거절인데 모델 원문과 인용이 그대로 나간다.**
- 두 실수의 값이 다르다. 답을 지우는 쪽이 훨씬 나쁘다. 그래서 정밀도를 먼저 지키고 재현율은 되는 만큼만 올렸다.

**문장 단위 규칙**
가르려는 것: 거절은 "이 질문에 답할 근거가 자료에 없다"는 말이고, 정답은 "자료가 이렇게 말한다"는 말이다. 자료가 하는 말이 부정문이어도 정답이다.
답을 문장으로 나눠 **모든 문장이 "없음 서술"** 이고 첫 문장에 `제공된 자료로는`이 있을 때만 PARAPHRASE다. 문장 하나가 없음 서술이려면:
1. 끝 서술어가 두 꼴 중 하나다. (가) `제공된 자료로는 … 확인/답변/판단할 수 없`(같은 문장에 `제공된 자료로는`이 있어야 한다). (나) 주어가 `정보/내용`이거나 자리가 `자료에/문서에`이고 `없`, `포함/명시/언급되어 있지 않`으로 끝난다.
2. 출처 표지(`따르면`, `의하면`, `에서는`, `바로는`)가 없다.
3. 인용 표시 `[n]`으로 끝나지 않는다. 문장 끝의 인용은 "근거가 있다"는 모델의 주장이다.
4. 숫자가 없다(인용 표시 `[1]` 제외).
5. "…지만/…으나"로 꺾이면 앞 절이 자료 설명(`…을 다루고 있으나`)이다.

- 어간을 `확인/답변/판단`으로 묶은 이유: "…할 수 없습니다"를 다 받으면 "만기 전에는 **중도해지할 수 없습니다** [1]"라는 정답이 거절이 된다.
- (나)의 주어를 `정보/내용`으로 묶은 이유: "법인은 가입 대상에 **포함되지 않습니다**", "면제하는 **규정은 없습니다**"는 자료의 내용을 전하는 정답이다. 2·3번과 함께 리뷰 뒤에 더한 조건이다.
- 숫자를 막은 이유: "[1]에는 연체이자율이 연 3%p라고 명시되어 있지만 … 은 언급되지 않았습니다"는 거절 이유처럼 생겼지만 3%p가 질문 절반의 답이었다. 판정기는 질문을 보지 않으므로 그 수치가 답인지 알 수 없다. 모르면 답변 쪽에 둔다.

**측정한 정밀도가 말해 주지 않는 것 (리뷰에서 나온 오탐)**
처음 규칙은 fixture 150개에서 정밀도 1.000(34/34)이었다. 그런데 리뷰어가 "자료 [1]에 따르면 미성년자는 가입 대상에 포함되지 않습니다"(정답)를 넣자 거절로 판정했고, `answer()`에서 답이 사라졌다.
- 정밀도는 **데이터가 지나간 영역**에서만 뜻이 있다. fixture의 거절 아닌 109개 가운데 "첫 문장이 자료를 가리키고 숫자가 없는" 출력은 0개였다. 규칙이 위험한 바로 그 영역에 표본이 하나도 없었으니, 1.000은 그 오탐에 대해 아무것도 말해 주지 않았다.
- 테스트도 같은 구멍이 있었다. "…할 수 없습니다가 정답인 경우"로 넣은 문장이 규칙에 걸리지 않는 어간(`중도해지`, `질권설정`)과 자료를 가리키지 않는 꼴뿐이었다. 통과하는 예만 고른 셈이다.
- 고친 방법: 실패하는 테스트 41문장을 먼저 넣고(처음 규칙은 31개를 거절로 봤다), 규칙을 좁혔다. 재현율이 0.829 → 0.732로 내려갔다. 정밀도를 지키려고 낸 값이다.
- 그래도 남는 것: 고친 영역은 **합성 문장으로만** 확인했다. 그리고 "제공된 자료로는 전화로 본인 여부를 확인할 수 없습니다"(인용 없음)는 거절 문구와 글자가 같아 규칙으로 가를 수 없다. 테스트에 알려진 한계로 적어 두었다.

**라벨을 먼저, 규칙은 나중에**
출력 150개를 읽고 `refusal / answer / partial` 라벨을 먼저 확정해 커밋한 뒤 판정기를 만들었다. 순서가 반대면 "규칙이 틀린 항목"을 볼 때마다 라벨을 규칙 쪽으로 고치고 싶어지고, 그러면 정밀도는 규칙이 자기 자신을 채점한 숫자가 된다.

**다듬기 묶음과 검증 묶음**
150개 중 실행 2개(100개)로 규칙을 다듬고, 나머지 실행 1개(50개)는 규칙을 확정한 뒤 한 번만 쟀다. 머신러닝의 train/test 분리와 같은 생각이다. 규칙도 데이터를 보고 만들면 그 데이터에 과적합된다.
- 결과: 정밀도는 둘 다 1.000, 재현율은 0.821 → 0.538. 검증 묶음에서 PARAPHRASE로 잡은 거절은 0개다(바꿔 말한 거절 6개 중 0개). 놓친 것은 "찾을 수 없습니다", "담고 있지 않습니다", "답변**을** 할 수 없습니다"처럼 다듬기 묶음에 없던 표현이다. 좁힌 규칙은 본 적 있는 표현 밖으로 거의 일반화하지 못한다.
- 검증 묶음을 보고 그 표현을 규칙에 넣으면 숫자는 오르지만, 그 숫자는 더 이상 "처음 보는 출력에서의 성능"이 아니다. 그래서 넣지 않고 다음 실험으로 남겼다.

**지표가 숨기고 있던 것**
거절 정확도는 `거절했나 == 범위 밖 질문인가`다. 검색이 근거를 못 가져온 5문항에서 모델이 "자료에 없다"고 한 것은 받은 자료로는 옳은 행동인데 이 지표로는 오답이다. 예전 판정은 그 거절들을 못 알아봐서 "답했다"로 세었고, 그래서 우연히 정답 처리가 됐다. 기준선 실행에서 새 판정은 범위 밖 4문항을 되찾고 검색 실패 3문항을 잃어 전체가 0.860 → 0.880이다. **평균은 한 문항 올랐는데 안에서는 7문항이 뒤집혔다.** 그래서 실험 기록은 평균이 아니라 qtype별 값과 뒤집힌 문항 번호를 적는다.

**근거 기준 거절 지표 (검색 실패와 생성 실패를 가른다)**
RAG의 답변 단계가 할 일은 "받은 자료에 맞게 행동하는 것"이다. 그래서 정답을 질문 유형이 아니라 **프롬프트에 근거가 들어왔는가**로 정한다: 근거가 있으면 답변, 없으면 거절. `evidence_in_context = recall_at_k > 0`이고, 근거 둘 중 하나만 들어와도 "있음"이다.
- 2×2로 보면: 근거 있음 + 답변(정상), 근거 있음 + 거절(**과잉 거절**), 근거 없음 + 거절(**옳은 거절**), 근거 없음 + 답변(**환각 위험**).
- 기준선 실행: strict 판정 + 기존 지표 0.860 → 새 판정 + 근거 기준 0.900. 오답 5건은 과잉 거절 3건과 판정기가 놓친 거절 2건(017, 029)이다.
- 놓치는 것: 답의 내용. "근거 없이 답함"이 틀린 답이라는 보장도, "근거 있고 답함"이 맞는 답이라는 보장도 없다. 그리고 "근거"는 골든셋 라벨이라 대체 근거로 답한 문항은 잘못 분류될 수 있다.

## 왜 이렇게 했나 (대안과 비교)

- **규칙 vs LLM-judge**: 거절 판정은 `/ask` 요청마다 도는 코드다. LLM을 한 번 더 부르면 요청마다 LLM 호출 한 번만큼 응답이 늦어지고, 판정이 실행마다 달라지고, 판정기 자체를 다시 사람이 보정해야 한다. 규칙은 0ms에 가깝고, 같은 입력에 늘 같은 답을 내고, 왜 그렇게 판정했는지 문장 단위로 설명할 수 있다. 대신 표현이 바뀌면 놓친다(검증 묶음의 재현율 0.538).
- **구조화 출력(`{"refused": true}`) vs 규칙**: 모델이 스스로 표시하게 하는 편이 더 근본적이다. 하지만 프롬프트를 바꾸면 답변 전체가 달라져 "판정만 바꾼 효과"를 따로 볼 수 없다. 이번에는 변수 하나만 바꾸려고 판정 규칙만 건드렸고, 프롬프트는 다음 실험이다.
- **"거절 문구가 어디든 있으면 거절" vs 문장 전부 검사**: 앞의 것은 "일반 예금은 1억원까지 보호됩니다 [1]. 퇴직연금 한도는 제공된 자료로는 확인할 수 없습니다."(부분 답변)를 지운다. 기준선 문서가 "앞에서 망설이고 실제로 답한 문항"으로 꼽은 012, 024, 039, 042도 위험하다. 그래서 모든 문장이 없음 서술이어야 한다는 조건을 걸었다.
- **PARAPHRASE도 정해진 문구로 바꾼다**: 바꾸지 않으면 거절 이유에 붙은 무관한 인용(기준선 046: 2개)이 근거처럼 화면에 나간다. 대신 "자료에는 정기예금만 있습니다" 같은 설명도 사라진다. 원문은 `llm.text`와 `raw_answer`에 남겨 디버깅과 재채점에 쓴다.
- **`refusal_accuracy`의 뜻을 바꾸고 `_strict`를 따로 둔다**: 예전 보고서와 이어서 볼 수 있게, 예전 방식의 값을 같은 보고서에 함께 남긴다. 새 보고서 하나만 봐도 전후 차이가 보인다.
- **API에는 `refusal_kind`를 내보내지 않는다**: 계획의 제약(필드 추가 없음)이다. `AskResponse`는 `Answer`에서 필드를 하나씩 골라 만들기 때문에 `Answer`에 필드를 더해도 새지 않는다. 테스트로 응답의 키 집합을 확인했다.

## 코드 읽는 순서

3. `tests/generation/test_refusal.py` — EXACT 목록, 기준선의 실제 거절 4건, NONE이어야 하는 문장들(부분 답변, "…할 수 없습니다"가 정답), fixture 정밀도 단언.

5. `src/axbuilder/eval/metrics.py`의 `grounded_refusal_correct`, `src/axbuilder/eval/run.py`의 `_record`, `_SUMMARY_KEYS`, `_REFUSAL_COUNTS`, `summarize`, `format_markdown` — 더한 줄만.
6. `scripts/rescore_refusals.py` — `rescore`(문항별 전후) → `format_rescore`(표).
7. `docs/experiments/2026-11-11-refusal-detection.md` — 수치, 리뷰에서 나온 오탐과 수정, 틀린 판정 11개, 한계.

## 면접 예상 질문과 답

**Q1. 왜 LLM-judge가 아니라 규칙으로 거절을 판정했나요?**
거절 판정이 평가에서만이 아니라 서비스의 요청 경로에서 돌기 때문입니다. LLM을 한 번 더 부르면 응답마다 지연과 비용이 늘고, 같은 답에 판정이 달라질 수 있고, 판정용 LLM이 맞는지를 또 검증해야 합니다. 규칙은 결정적이고 왜 그렇게 판정했는지 문장 단위로 설명됩니다. 대신 표현이 조금만 달라져도 놓칩니다. 규칙을 만들 때 안 쓴 출력 50개에서는 재현율이 0.821에서 0.538로 내려갔고, 그 묶음의 바꿔 말한 거절 6개는 하나도 잡지 못했습니다. 그래서 "이 모델과 이 프롬프트에서 검증한 규칙"이라고 문서에 적었습니다. 더 근본적인 방법은 모델이 구조화된 출력으로 거절을 직접 표시하게 하는 것이고 다음 실험으로 잡아 두었습니다.

**Q2. 정밀도를 재현율보다 우선한 이유는요?**
두 실수의 피해가 다르기 때문입니다. 판정기가 정상 답을 거절로 잘못 보면 사용자는 답을 통째로 잃고 "확인할 수 없습니다"만 봅니다. 반대로 거절을 놓치면 모델이 쓴 거절 문장이 그대로 나갈 뿐입니다. 내용은 여전히 "자료에 없다"입니다. 그래서 애매하면 답변으로 두었습니다. 리뷰에서 오탐이 나왔을 때도 같은 원칙으로 규칙을 좁혔고, 재현율이 0.829에서 0.732로 내려가는 것을 받아들였습니다. 150개에서 거절로 판정한 30개는 모두 진짜 거절이었고, 진짜 거절 41개 중 11개는 놓쳤습니다.

**Q3. "같은 출력으로 전후를 비교했다"는 게 무슨 뜻이고 왜 중요한가요?**
로컬 LLM은 같은 질문에도 실행마다 답이 달라집니다. 같은 설정으로 세 번 돌린 실행에서 예전 규칙이 잡은 범위 밖 거절은 2/6, 2/6, 4/6으로 달랐습니다. 판정 규칙을 바꾸고 모델을 다시 돌려 비교하면, 숫자가 달라진 것이 규칙 때문인지 샘플링 때문인지 가를 수 없습니다. 그래서 이미 저장된 모델 출력 150개를 그대로 두고 판정 규칙만 예전 것과 새 것으로 바꿔 채점했습니다. 이러면 차이는 전부 규칙 때문입니다. 저장된 답이 예전 규칙으로 한 번 가공된 텍스트라는 점이 걸려서, 가공 전 원문으로도 판정해 150개 모두 결과가 같다는 것을 확인했습니다.

**Q4. 거절 정확도가 왜 안 올랐고, 그래서 무엇을 바꿨나요?**
판정을 고쳤는데 숫자가 거의 그대로여서, 판정과 지표 정의를 분리해서 봤습니다. 같은 출력에 [옛 판정 + 기존 지표], [새 판정 + 기존 지표], [새 판정 + 새 지표]를 차례로 적용해 한 번에 하나만 바꿨습니다. 기준선 실행에서 0.860, 0.880, 0.900이 나왔습니다. 첫 두 줄이 비슷한 것은 기존 지표가 "범위 밖이 아니면 답해야 정답"이라서, 검색이 근거를 못 가져와 모델이 옳게 거절한 것을 오답으로 세기 때문이었습니다. 범위 밖에서 네 문항이 오르고 검색 실패 문항에서 세 문항이 내려갔습니다. 그래서 `grounded_refusal_correct`를 더했습니다. 프롬프트에 들어간 자료에 정답 근거가 있으면 답해야 맞고, 없으면 거절해야 맞습니다. 이러면 검색 실패는 Recall@k가, 생성 단계의 실패는 거절 지표가 따로 잽니다. 내역도 셋으로 남깁니다: 근거가 있는데 거절(과잉 거절, 2~3건으로 그대로), 근거가 없어서 거절(옳은 행동), 근거가 없는데 답함(환각 위험). 마지막 것은 세 실행의 11건을 직접 읽었는데 답을 지어낸 것은 없었고 10건이 판정기가 놓친 거절이었습니다. 새 지표가 판정기의 재현율에 민감하다는 것도 여기서 알았습니다. 한 실행은 오히려 0.900에서 0.800으로 내려갔습니다. 한계는 "근거가 있다"가 골든셋 라벨 기준이라는 점, 그리고 답의 내용이 맞는지는 이 지표가 보지 않는다는 점입니다.

**Q5. 정밀도가 1.000이었는데 왜 리뷰에서 오탐이 나왔나요?**
정밀도는 평가 데이터가 지나간 영역에 대해서만 말해 주기 때문입니다. 처음 규칙은 "첫 문장이 자료를 가리키고, 모든 문장이 포함·명시·확인되지 않는다 또는 규정·근거가 없다로 끝나면 거절"이었습니다. 실제 출력 150개에서는 오탐이 없었습니다. 그런데 리뷰어가 "자료에 따르면 미성년자는 가입 대상에 포함되지 않습니다"라는 정답을 넣자 거절로 판정됐고 답이 사라졌습니다. 세어 보니 거절이 아닌 출력 109개 중 그런 꼴(첫 문장이 자료를 가리키고 숫자가 없는 답)은 0개였습니다. 표본이 없는 영역이었으니 1.000은 아무 근거가 되지 못했습니다. 제 테스트도 규칙에 걸리지 않는 문장만 골라 넣어 통과하고 있었습니다. 고칠 때는 실패하는 문장 41개를 먼저 테스트로 넣고, "거절은 근거가 없다는 말이고 정답은 자료가 이렇게 말한다는 말"이라는 구분에 맞춰 규칙을 좁혔습니다. 출처 표지가 있거나 인용으로 끝나는 문장은 답으로 보고, 주어가 정보·내용일 때만 "없다"를 거절로 봅니다. 배운 것은 세 가지입니다. 지표를 볼 때 분모가 어떤 입력으로 이루어졌는지 먼저 본다. 규칙을 만든 사람이 고른 예시는 규칙의 맹점을 그대로 물려받으니 다른 사람이 반례를 만들어야 한다. 그리고 고친 뒤에도 그 영역은 합성 문장으로만 확인했다고 한계에 적는다.
