# Task 15 — 모델 선택, 빠른 만들기, 한 줄 실행

계획: [`2026-11-10-web-ui.md`](../superpowers/plans/2026-11-10-web-ui.md) 2부의 Task 15. 커밋 `74cff85`(워크스페이스별 모델, 모델 목록), `0b92f9c`(`axb` 명령), `448df93`(화면: 빠른 만들기, 모델 선택).

## 이 작업이 하는 일

사용자 요청은 "딱 켜서 원하는 로컬 모델을 고르고 파일을 넣으면 어시스턴트가 만들어지게"였다. 세 가지를 더했다.

| 무엇 | 내용 |
|---|---|
| `axb serve` | 명령 하나로 서버를 127.0.0.1에 띄우고 브라우저를 연다. 시작할 때 Ollama 연결과 기본 모델 유무를 한 줄씩 알린다 |
| 모델 선택 | `GET /models`가 Ollama에 설치된 모델을 알려 준다. 워크스페이스마다 `llm_model`을 저장하고(`PATCH /workspaces/{id}`), 질문은 그 모델로 답한다. 응답의 `model`이 실제로 답한 모델이다 |
| 빠른 만들기 | 화면의 3단계 대화상자: ① 이름 ② 모델 ③ 파일. "만들기"를 누르면 워크스페이스 생성 → 파일마다 업로드 → 색인을 차례로 하고 단계별 진행과 실패한 파일의 이유를 보여 준다 |

브라우저에서 확인한 것(세션 주인, 2026-11-11, 실제 서버와 `qwen3.5:4b-q4_K_M`): 빠른 만들기 3단계를 한글 이름 "우리 은행 규정"(제안된 id `uri-eunhaeng-gyujeong`)과 한글 파일 이름 2개로 끝까지 진행했다(청크 7개). 그 문서로 질문해 제2조를 인용한 답을 받았다.

## 핵심 개념

**Ollama의 모델 목록 (`/api/tags`).** Ollama는 로컬 HTTP 서버이고 `GET /api/tags`가 설치된 모델의 이름·크기·파라미터 수·양자화 수준을 준다. `list_ollama_models`가 이것을 읽는다. 시간 제한은 3초다(`OLLAMA_TAGS_TIMEOUT`). 화면이 주기적으로 부르므로 Ollama가 꺼져 있어도 오래 기다리지 않아야 한다. 결과는 세 갈래다: 연결 자체가 안 됨(`OllamaNotRunningError`), 연결은 됐는데 응답이 이상함(`LLMUnavailableError`), 정상. `/models`는 어느 경우에도 200을 주고 `available`과 `hint`(다음에 할 일)로 알린다. 화면이 오류 화면이 아니라 안내를 보여 주게 하려는 것이다(Review Focus 5).

**양자화(`q4_K_M`).** 모델 가중치를 16·32비트 실수 대신 4비트쯤으로 줄여 저장한 것이다. 크기와 GPU 메모리가 줄고 품질이 조금 떨어진다. 8GB GPU에서 임베딩 모델과 함께 올리려면 필요하다. 화면이 모델마다 크기와 양자화를 보여 주는 이유다.

**태그 없는 이름은 `:latest`.** Ollama에서 `qwen3`은 `qwen3:latest`와 같다. 기본 모델이 설치됐는지 볼 때 `has_ollama_model`이 이 규칙을 따른다. 그냥 문자열로 비교하면 설치된 모델을 없다고 안내한다.

**모델 이름 형식 검사.** 형식은 `^[A-Za-z0-9][A-Za-z0-9._/:-]{0,127}$`다. 이 이름은 Ollama 요청에 들어가고, "`ollama pull <이름>`" 안내 문구에 들어가 사용자가 터미널에 붙여 넣는다. 공백·셸 문자·줄바꿈이 들어 있으면 안내 문구가 다른 명령이 된다. 그래서 저장할 때(`Workspace`, `WorkspacePatch`)와 목록을 읽을 때(형식에 안 맞는 이름은 뺀다) 모두 검사한다.

**모델별 클라이언트 캐시.** `OllamaClient`는 HTTP 연결을 쥐고 있다. 질문마다 새로 만들지 않고 모델 이름별로 하나씩 만들어 다시 쓴다(`_Service.llm_for`). 어느 모델이든 타임아웃, `think: false`, `num_ctx` 8192는 같다. 클라이언트가 정하는 값이기 때문이다.

**PATCH의 "모르는 필드 거절".** `WorkspacePatch`는 `extra="forbid"`이고 `llm_model`에 기본값이 없다. `{"name": "새 이름"}`을 보내면 422다. 조용히 무시하면 보낸 쪽은 바뀐 줄 안다. `null`은 "서버 기본 모델로 되돌리기"라는 뜻이 있으므로, 빈 본문 `{}`과 구분하려고 필드를 필수로 했다.

**한글 이름에서 id 만들기.** 워크스페이스 id는 폴더 이름이라 `^[a-z0-9-]{2,32}$`만 된다. 화면은 한글 음절을 초성·중성·종성으로 나눠 글자 단위로 로마자로 옮겨 id를 **제안**한다(`naming.js`의 `romanize`, `suggestWorkspaceId`). 발음 규칙은 적용하지 않는다. 제안값이고 사용자가 고칠 수 있기 때문이다. 문서 id는 다르게 한다. 파일 이름에서 영문·숫자만 남기고, 남는 것이 없거나(한글 이름) 겹치면 `doc-001`식 번호를 준다(`assignDocIds`). 서버가 최종 검사하므로 화면의 규칙은 "빨리 알려 주기"용이다.

## 왜 이렇게 했나 (대안과 비교)

- **모델 내려받기는 서버가 하지 않는다.** `ollama pull`은 수 GB를 받는다. 서버가 대신하면 진행 표시, 취소, 디스크 부족, 누가 무엇을 받게 했는지를 다뤄야 한다. 화면은 명령을 보여 주고 복사하게 한 뒤 "다시 확인"으로 목록을 다시 읽는다. 질문할 때 모델이 없으면 Ollama의 404를 503과 `ollama pull <이름>` 안내로 바꾼다.
- **`llm_model`은 선택 필드, 기본값 `None`.** 이 필드가 생기기 전의 `workspace.yaml`이 그대로 읽힌다(테스트가 예전 파일을 읽어 확인한다). `None`은 "서버 기본 모델"이라 서버 설정(`AXB_LOCAL_MODEL`)을 바꾸면 함께 바뀐다. 화면도 기본 모델을 고르면 이름을 저장하지 않고 비워 둔다.
- **cloud 모드에서는 워크스페이스 설정을 무시한다.** `AXB_LLM_MODE=cloud`면 `llm_model`(로컬 모델 이름)을 Claude API에 보내지 않고 설정된 Claude 모델만 쓴다. `/models`는 그 모델 하나와 "고를 수 없다"는 안내를 준다.
- **응답의 `model`은 실제로 답한 모델.** LLM이 알려 준 이름을 쓴다. LLM을 부르지 않고 거절했으면 그 워크스페이스가 쓸 모델 이름이다. 모델을 바꿔 가며 비교할 때 어느 답이 어느 모델에서 왔는지 남는다.
- **빠른 만들기의 기본값은 좁은 쪽.** 역할은 `관리자`=[public, internal] 하나, 모든 파일의 등급은 `internal`이다. 세 단계만 누른 사람의 문서가 `public`으로 들어가 나중에 만든 낮은 역할에 보이면 안 된다. 등급을 넓히는 것은 "세부 설정"을 펼쳐 직접 고를 때만 된다. 문서 종류는 파일 이름의 낱말(약관, 설명서, 지침 등)로 추정하고 모르면 `other`다. 계획은 "확장자로 추정"이라고 적었지만 확장자만으로는 종류를 알 수 없어 이름을 본다.
- **한 번에 하는 API를 만들지 않고 화면이 차례로 부른다.** 빠른 만들기는 기존 API 셋(`POST /workspaces`, `/documents`, `/index`)을 순서대로 부른다. 서버에 "한 번에 만들기" API를 더하면 검증 경로가 둘이 된다. 대신 파일 하나가 실패해도 나머지는 계속 올리고, 실패한 파일은 이유와 함께 남긴다. 하나라도 올라갔으면 색인한다.
- **`axb serve`: uvicorn을 감싼 이유.** `uvicorn axbuilder.api.main:app`을 외우지 않아도 되고, 세 가지를 대신 챙긴다. (1) 포트가 이미 쓰이고 있으면 uvicorn의 긴 로그 대신 한 줄로 알리고 종료 코드 1. (2) 브라우저는 서버가 포트에서 연결을 받기 시작한 뒤에 연다. 먼저 열면 "연결할 수 없음" 화면이 뜬다. 60초 안에 안 뜨면 열지 않는다. (3) Ollama가 꺼져 있어도 서버는 띄운다. 화면이 할 일을 안내하기 때문이다. 쓸 수 없는 `AXB_*` 값은 한 줄로 알리고 종료 코드 2다.
- **무거운 import는 명령을 실행할 때.** `axb --version`이 임베딩·LLM 코드를 끌어오지 않도록 `create_app`은 `_serve` 안에서 import한다.

## 면접 예상 질문과 답

**Q1. 워크스페이스마다 다른 모델을 쓰게 한 이유는요?**
문서 성격과 PC 사양이 다르기 때문입니다. 작은 모델로 충분한 워크스페이스와 큰 모델이 필요한 워크스페이스가 한 서버에 같이 있을 수 있습니다. 응답에 실제로 답한 모델 이름을 넣어서, 같은 질문을 모델만 바꿔 비교하기도 쉽습니다. 구현은 LLM 프로토콜 하나 뒤에 모델 이름별 클라이언트를 캐시하는 정도라 작습니다.

**Q2. Ollama가 꺼져 있으면 어떻게 되나요?**
서버는 그대로 뜹니다. `/models`가 200으로 `available: false`와 할 일(`ollama serve`)을 주고, 화면이 그것을 보여 줍니다. 질문을 하면 503과 같은 안내가 나옵니다. 모델만 없는 경우는 `ollama pull <이름>` 명령을 보여 줍니다. "왜 안 되는지 모르는 상태"를 만들지 않는 것이 목표였습니다.

**Q3. 모델 이름을 왜 정규식으로 검사하나요?**
이 이름이 "`ollama pull <이름>`" 안내에 들어가 사용자가 터미널에 붙여 넣기 때문입니다. 이름에 `;`나 공백, 줄바꿈이 있으면 안내 문구가 다른 명령이 됩니다. 그래서 저장할 때 형식을 검사하고, Ollama가 알려 준 목록에서도 형식에 안 맞는 이름은 뺍니다.

**Q4. 한글 파일 이름은 어떻게 처리하나요?**
파일 이름은 저장 경로에 쓰지 않습니다. 저장 이름은 문서 id이고 소문자·숫자·하이픈만 됩니다. 화면이 파일 이름에서 영문·숫자를 뽑아 id를 만들고, 남는 글자가 없거나 겹치면 `doc-001`식 번호를 줍니다. 원래 파일 이름은 제목과 출처에 남습니다. 한글 파일 이름 2개로 끝까지 만들어 질문까지 확인했습니다.

**Q5. 빠른 만들기에서 문서 등급 기본값이 왜 internal인가요?**
틀렸을 때 덜 위험한 쪽이기 때문입니다. `public`이 기본이면 내부 문서를 올리고 등급을 안 바꾼 사람의 문서가 모든 역할에 보입니다. `internal`이 기본이면 최악의 경우 "봐야 할 사람이 못 본다"이고, 그것은 바로 드러나서 고칠 수 있습니다.
