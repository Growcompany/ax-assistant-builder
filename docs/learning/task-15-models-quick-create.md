# Task 15 — 모델 선택, 빠른 만들기, 한 줄 실행

계획은 [`2026-11-10-web-ui.md`](../superpowers/plans/2026-11-10-web-ui.md) 2부의 Task 15입니다. 커밋은 `74cff85`(워크스페이스별 모델, 모델 목록), `0b92f9c`(`axb` 명령), `448df93`(화면: 빠른 만들기, 모델 선택)입니다.

## 이 작업이 하는 일

사용자의 요청은 "딱 켜서 원하는 로컬 모델을 고르고 파일을 넣으면 어시스턴트가 만들어지게"였습니다. 그래서 세 가지를 더했습니다.

| 기능 | 내용 |
|---|---|
| `axb serve` | 명령 하나로 서버를 127.0.0.1에 띄우고 브라우저를 엽니다. 시작할 때 Ollama 연결 상태와 기본 모델이 있는지를 한 줄씩 알려 줍니다 |
| 모델 선택 | `GET /models`가 Ollama에 설치된 모델 목록을 알려 줍니다. 워크스페이스마다 `llm_model`을 저장하고(`PATCH /workspaces/{id}`), 질문하면 그 모델이 답합니다. 응답의 `model`에는 실제로 답한 모델이 들어갑니다 |
| 빠른 만들기 | 화면에서 ① 이름 ② 모델 ③ 파일 순서로 3단계 대화상자를 거칩니다. "만들기"를 누르면 워크스페이스 생성, 파일별 업로드, 색인을 차례로 진행하고, 단계별 진행 상황과 실패한 파일의 이유를 보여 줍니다 |

구현 세션의 에이전트가 2026-11-11에 실제 서버와 `qwen3.5:4b-q4_K_M`으로 브라우저에서 확인했습니다. 빠른 만들기 3단계를 한글 이름 "우리 은행 규정"(제안된 id `uri-eunhaeng-gyujeong`)과 한글 파일 이름 2개로 끝까지 진행했고, 청크 7개가 만들어졌습니다. 그 문서로 질문해 제2조를 인용한 답을 받았습니다.

## 핵심 개념

**Ollama의 모델 목록 (`/api/tags`).** Ollama는 로컬 HTTP 서버이고, `GET /api/tags`를 부르면 설치된 모델의 이름·크기·파라미터 수·양자화 수준을 알려 줍니다. `list_ollama_models`가 이 응답을 읽습니다. 시간 제한은 3초입니다(`OLLAMA_TAGS_TIMEOUT`). 화면이 주기적으로 부르는 API라서, Ollama가 꺼져 있을 때 오래 기다리면 안 됩니다. 결과는 세 경우로 나뉩니다. 연결 자체가 안 되는 경우(`OllamaNotRunningError`), 연결은 됐지만 응답이 이상한 경우(`LLMUnavailableError`), 그리고 정상인 경우입니다. `/models`는 어느 경우든 200으로 응답하고, `available`과 `hint`(다음에 할 일)로 상태를 알립니다. 화면이 오류 화면 대신 안내를 보여 주게 하려는 것입니다(Review Focus 5).

**양자화(`q4_K_M`).** 모델 가중치를 16·32비트 실수 대신 4비트 정도로 줄여 저장하는 방법입니다. 파일 크기와 GPU 메모리 사용량이 줄고 품질은 조금 떨어집니다. 8GB GPU에 임베딩 모델과 함께 올리려면 양자화가 필요합니다. 화면이 모델마다 크기와 양자화 수준을 보여 주는 것도 이 때문입니다.

**태그 없는 이름은 `:latest`.** Ollama에서 `qwen3`은 `qwen3:latest`와 같은 모델입니다. `has_ollama_model`은 기본 모델이 설치됐는지 확인할 때 이 규칙을 따릅니다. 단순히 문자열로 비교하면 설치된 모델을 없다고 안내하게 됩니다.

**모델 이름 형식 검사.** 허용하는 형식은 `^[A-Za-z0-9][A-Za-z0-9._/:-]{0,127}$`입니다. 모델 이름은 Ollama 요청에도 들어가고, 사용자가 터미널에 붙여 넣는 "`ollama pull <이름>`" 안내 문구에도 들어갑니다. 이름에 공백·셸 문자·줄바꿈이 섞여 있으면 안내 문구가 전혀 다른 명령이 됩니다. 그래서 저장할 때(`Workspace`, `WorkspacePatch`)와 목록을 읽을 때 모두 검사하고, 목록에서는 형식에 맞지 않는 이름을 뺍니다.

**모델별 클라이언트 캐시.** `OllamaClient`는 HTTP 연결을 들고 있습니다. 그래서 질문마다 새로 만들지 않고, 모델 이름마다 하나씩 만들어 재사용합니다(`_Service.llm_for`). 타임아웃, `think: false`, `num_ctx` 8192는 모델과 상관없이 같습니다. 모델이 아니라 클라이언트가 정하는 값이기 때문입니다.

**PATCH의 "모르는 필드 거절".** `WorkspacePatch`는 `extra="forbid"`로 설정했고 `llm_model`에는 기본값이 없습니다. 그래서 `{"name": "새 이름"}`을 보내면 422가 납니다. 모르는 필드를 조용히 무시하면 보낸 쪽은 값이 바뀐 줄 알기 때문입니다. `null`은 "서버 기본 모델로 되돌리기"라는 뜻이 있으므로, 빈 본문 `{}`과 구분하려고 이 필드를 필수로 했습니다.

**한글 이름에서 id 만들기.** 워크스페이스 id는 폴더 이름으로 쓰이므로 `^[a-z0-9-]{2,32}$` 형식만 허용합니다. 화면은 한글 음절을 초성·중성·종성으로 나눈 뒤 글자 단위로 로마자로 옮겨 id를 **제안**합니다(`naming.js`의 `romanize`, `suggestWorkspaceId`). 발음 규칙은 적용하지 않습니다. 어디까지나 제안값이고 사용자가 고칠 수 있기 때문입니다. 문서 id는 방식이 다릅니다. 파일 이름에서 영문·숫자만 남기고, 남는 글자가 없거나(한글 이름) 다른 id와 겹치면 `doc-001` 같은 번호를 붙입니다(`assignDocIds`). 최종 검사는 서버가 하므로, 화면의 규칙은 사용자에게 문제를 빨리 알려 주는 용도입니다.

## 왜 이렇게 했나 (대안과 비교)

- **모델 내려받기는 서버 밖에서.** `ollama pull`은 몇 GB씩 내려받습니다. 서버가 이 일을 대신하면 진행 표시, 취소, 디스크 부족, 누가 무엇을 받게 했는지까지 다뤄야 합니다. 그래서 화면은 명령을 보여 주고 복사하게 한 뒤, "다시 확인"을 누르면 목록을 다시 읽습니다. 질문할 때 모델이 없으면 Ollama가 준 404를 503과 `ollama pull <이름>` 안내로 바꿔 응답합니다.
- **`llm_model`은 선택 필드, 기본값 `None`.** 그래서 이 필드가 생기기 전에 만든 `workspace.yaml`도 그대로 읽힙니다. 테스트에서 예전 파일을 읽어 확인합니다. `None`은 "서버 기본 모델"이라는 뜻이라, 서버 설정(`AXB_LOCAL_MODEL`)을 바꾸면 함께 바뀝니다. 화면에서도 기본 모델을 고르면 이름을 저장하지 않고 비워 둡니다.
- **cloud 모드에서는 워크스페이스 설정 무시.** `AXB_LLM_MODE=cloud`이면 `llm_model`(로컬 모델 이름)을 Claude API에 보내지 않고, 설정된 Claude 모델만 씁니다. 이때 `/models`는 그 모델 하나와 "고를 수 없다"는 안내를 응답합니다.
- **응답의 `model`은 실제로 답한 모델.** LLM이 알려 준 이름을 그대로 씁니다. LLM을 부르지 않고 거절한 경우에는 그 워크스페이스가 쓸 모델 이름을 넣습니다. 그래서 모델을 바꿔 가며 비교할 때 어느 답이 어느 모델에서 나왔는지 기록에 남습니다.
- **빠른 만들기의 기본값은 좁은 쪽.** 역할은 `관리자`=[public, internal] 하나만 만들고, 모든 파일의 등급은 `internal`로 둡니다. 세 단계만 누르고 끝낸 사람의 문서가 `public`으로 들어가, 나중에 만든 낮은 역할에게 보이면 안 되기 때문입니다. 등급을 넓히려면 "세부 설정"을 펼쳐 직접 골라야 합니다. 문서 종류는 파일 이름에 든 낱말(약관, 설명서, 지침 등)로 추정하고, 알 수 없으면 `other`로 둡니다. 계획에는 "확장자로 추정"이라고 적혀 있었지만, 확장자만으로는 종류를 알 수 없어서 파일 이름을 봅니다.
- **한 번에 만드는 API 대신 화면에서 차례로 호출.** 빠른 만들기는 기존 API 세 개(`POST /workspaces`, `/documents`, `/index`)를 순서대로 부릅니다. 서버에 "한 번에 만들기" API를 따로 더하면 검증 경로가 둘로 늘어납니다. 그 대신 화면에서는 파일 하나가 실패해도 나머지를 계속 올리고, 실패한 파일은 이유와 함께 목록에 남깁니다. 하나라도 올라갔으면 색인을 진행합니다.
- **uvicorn을 감싼 `axb serve`.** `uvicorn axbuilder.api.main:app`을 외우지 않아도 되고, 세 가지를 대신 챙겨 줍니다. (1) 포트가 이미 쓰이고 있으면 uvicorn의 긴 로그 대신 한 줄로 알리고 종료 코드 1로 끝냅니다. (2) 브라우저는 서버가 포트에서 연결을 받기 시작한 뒤에 엽니다. 먼저 열면 "연결할 수 없음" 화면이 뜨기 때문입니다. 60초 안에 서버가 뜨지 않으면 브라우저를 열지 않습니다. (3) Ollama가 꺼져 있어도 서버는 띄웁니다. 할 일은 화면이 안내하기 때문입니다. 쓸 수 없는 `AXB_*` 값이 있으면 한 줄로 알리고 종료 코드 2로 끝냅니다.
- **무거운 import는 명령을 실행할 때.** `axb --version`을 실행할 때 임베딩·LLM 코드까지 불러오지 않도록, `create_app`은 `_serve` 안에서 import합니다.

## 면접 예상 질문과 답

**Q1. 워크스페이스마다 다른 모델을 쓰게 한 이유는요?**
문서 성격도 다르고 쓰는 PC 사양도 다르기 때문입니다. 작은 모델로 충분한 워크스페이스와 큰 모델이 필요한 워크스페이스가 한 서버에 같이 있을 수 있습니다. 응답에 실제로 답한 모델 이름을 넣어 두었기 때문에, 같은 질문을 모델만 바꿔 비교하기도 쉽습니다. 구현은 LLM 프로토콜 하나 뒤에서 모델 이름별로 클라이언트를 캐시하는 정도라 크지 않았습니다.

**Q2. Ollama가 꺼져 있으면 어떻게 되나요?**
서버는 그대로 뜹니다. `/models`가 200으로 `available: false`와 할 일(`ollama serve`)을 응답하고, 화면이 그 안내를 보여 줍니다. 그 상태에서 질문하면 503과 함께 같은 안내가 나옵니다. 모델만 없는 경우에는 `ollama pull <이름>` 명령을 보여 줍니다. 사용자가 왜 안 되는지 모르는 상태를 만들지 않는 것이 목표였습니다.

**Q3. 모델 이름을 왜 정규식으로 검사하나요?**
모델 이름이 "`ollama pull <이름>`" 안내 문구에 들어가고, 사용자가 그 문구를 터미널에 붙여 넣기 때문입니다. 이름에 `;`나 공백, 줄바꿈이 있으면 안내 문구가 다른 명령이 됩니다. 그래서 저장할 때 형식을 검사하고, Ollama가 알려 준 목록에서도 형식에 맞지 않는 이름은 뺍니다.

**Q4. 한글 파일 이름은 어떻게 처리하나요?**
파일 이름은 저장 경로에 쓰지 않습니다. 저장 이름은 문서 id이고, 소문자·숫자·하이픈만 쓸 수 있습니다. 화면이 파일 이름에서 영문·숫자를 뽑아 id를 만들고, 남는 글자가 없거나 겹치면 `doc-001` 같은 번호를 붙입니다. 원래 파일 이름은 제목과 출처에 남습니다. 구현을 맡은 에이전트가 한글 파일 이름 2개로 끝까지 만들고 질문까지 해 보며 확인했습니다.

**Q5. 빠른 만들기에서 문서 등급 기본값이 왜 internal인가요?**
틀렸을 때 덜 위험한 쪽이기 때문입니다. `public`이 기본이면 내부 문서를 올리고 등급을 바꾸지 않은 사람의 문서가 모든 역할에 보입니다. `internal`이 기본이면 최악의 경우라도 봐야 할 사람이 못 보는 정도이고, 이런 문제는 바로 드러나서 고칠 수 있습니다.
