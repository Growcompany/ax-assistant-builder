# Task 26 — 골든셋 v1로 다시 재기 (리랭커, 검색기, 긴 조항 나누기, 답변)

## 이 작업이 하는 일

골든셋을 150문항으로 늘리고(Task 24) 긴 조항 나누기를 넣은(Task 25) 뒤, M-2 축소판의 질문을 다시 쟀다. 측정은 저장소 주인이 GPU로 돌렸고(검색 24회, 답변 9회), 이 작업은 저장된 보고서를 문항 단위로 다시 계산해 기록과 결정 문서로 정리했다. 코드는 바꾸지 않았다.

| 질문 | 답 | 어디에 |
|---|---|---|
| 리랭커가 검색을 올리나 | 127문항에서 세 검색기 모두 유의하게 오른다(답 문구 기준). 44문항에서는 비유의였다 | [골든셋 v1 기록](../experiments/2026-11-12-golden-v1.md), [ADR 0006 갱신](../adr/0006-reranker.md) |
| dense 대 hybrid | 갈리지 않는다. 리랭커를 붙이면 맞힌 문항이 같다 | 같은 기록, [ADR 0002 갱신](../adr/0002-hybrid-rrf.md) |
| 긴 조항 나누기 | 잘림은 10% → 0.3%인데 Recall은 한 문항 | [분할 기록](../experiments/2026-11-12-article-split.md), [ADR 0007](../adr/0007-article-split.md) |
| 리랭커가 답변을 좋게 하나 | 거절 지표는 좋아졌지만 실행 간 편차 안, 인용 정밀도는 그대로 | [답변 기록](../experiments/2026-11-12-answers-v1.md) |
| 권한 필터가 새나 | 상담원 역할에서 internal 청크 0, 인용 0, 내부 지침의 사실 0 | 같은 기록 |
| 부정문 정답에서 과잉 거절이 많나 | 많다(6회 모두 Fisher p ≤ 0.016). 프롬프트 한 줄로 줄었지만 채택하지 않음 | 같은 기록 |

## 핵심 개념

**정확 맥니마 검정과 검정력.** 두 조건을 같은 문항으로 비교할 때, 둘 다 맞히거나 둘 다 놓친 문항은 차이에 대한 정보가 없다. 맥니마는 한쪽만 맞힌 문항(불일치 문항) b, c만 보고 "b와 c가 반반이면 이런 쏠림이 나올 확률"을 이항분포로 계산한다. 불일치가 5 대 0이어도 p = 0.0625다. 표본이 크면 같은 쏠림 비율에서도 불일치 문항 수가 늘어 p가 작아진다. 이것이 검정력이다.

**여러 비교와 Holm 보정.** 비교를 20번 하면 효과가 없어도 p < 0.05가 한 번쯤 나온다. Holm은 p값을 작은 순서로 놓고 i번째에 (m − i + 1)을 곱해 0.05와 견주다가 처음 넘는 곳에서 멈춘다. Bonferroni(모두에 m을 곱함)와 같은 보장(가족 전체에서 하나라도 잘못 유의할 확률 ≤ 0.05)을 주면서 덜 보수적이다. 어려운 것은 "가족"을 어디까지로 보느냐다. 리랭커 비교 3개만 보면 세 검색기 모두 남고, 이 실험의 비교 11개를 한 가족으로 보면 BM25만 남는다.

**채점 규칙이 결론을 바꾼다.** 라벨 기준은 "근거 조항의 청크가 들어왔나", 답 문구 기준은 "답이 적힌 청크가 들어왔나"다. 상품설명서처럼 조항이 없는 문서와 나눈 조각에서 둘이 갈린다. 라벨 기준으로는 dense의 리랭커 효과가 비유의(p = 0.109)고, 리랭커 없는 분할의 손해(MRR 0.752 → 0.737)는 아예 보이지 않는다(라벨로는 0.847 → 0.854로 오름).

**측정 도구의 재현율이 지표를 만든다.** 거절 판정기는 오탐을 막으려고 좁힌 규칙이라 재현율이 낮다. 판정기가 놓친 거절은 "답함"으로 세어져 "근거 없이 답함"과 범위 밖 거절이 나쁘게 나온다. 이번에 그 지표의 50건을 읽어 보니 47건이 놓친 거절이었다. 숫자가 바뀌면 모델이 바뀐 것인지 측정이 바뀐 것인지부터 본다.

**실행 간 편차.** 검색은 결정적이지만 LLM 생성은 실행마다 다르다. 같은 조건을 두 번 돌리면 150문항 중 14~24문항에서 거절 여부가 바뀐다. 조건 사이의 차이가 이보다 작으면 효과라고 말하지 않는다.

## 왜 이렇게 했나 (대안과 비교)

- **보고서 요약값을 그대로 쓰지 않고 문항별 기록에서 다시 계산.** 요약값은 맞았지만, 문항 단위 검정, v0 부분과 새 부분 나누기, 나뉜 조항이 근거인 22문항 같은 부분집합 분석은 요약에 없다. 재계산은 남이 낸 숫자(세션 주인의 수치)와 대조하는 역할도 했다. 대조에서 "라벨 기준도 유의"와 "잘림 8.7% → 0.1%" 두 곳이 데이터와 달랐다.
- **판정기를 믿지 않고 원문을 읽기.** 대안은 LLM-judge(유료 API라 승인이 필요)와 사람 검수(검수표를 만들어 넘김)다. 이번에는 판정이 바뀌는 출력만 골라(바꿔 말한 거절 판정 21건, 범위 밖 "답함" 47건, 근거 없이 답함, 과잉 거절이 풀린 18건) 에이전트가 읽었고, 사람 검수가 아니라고 적었다.
- **Holm, 그리고 묶음을 여러 개 보여 주기.** 가족을 하나로 정해 그 결과만 보이면, 그 선택이 결론을 만든다. 계획이 정한 질문 단위(리랭커 3개)를 본문으로 하고, 넓힌 묶음의 결과를 나란히 적었다. FDR(Benjamini-Hochberg)은 "발견 목록"을 만들 때 쓰는데, 여기서는 기본값 하나를 정하는 결정이라 하나라도 틀리면 곤란한 쪽(FWER, Holm)을 골랐다.
- **잘림 위치를 토크나이저 대신 글자 위치로 추정.** 이 작업은 GPU·모델을 쓰지 않는 조건이라 다시 세지 않았다. 앞 기록의 실측(bank-044가 820~850자에서 잘림)과 Task 25의 글자당 토큰 비율로 800자를 경계로 잡고 "추정"이라고 적었다.

## 코드 읽는 순서

1. `src/axbuilder/eval/run.py`의 `_record`: 문항 기록의 필드(`recall_at_k_strict`, `reciprocal_rank_strict`, `evidence_in_context`, `refused`, `refusal_kind`, `raw_answer`, `citations`). 이번 분석이 쓴 값은 모두 여기서 나온다.
2. `src/axbuilder/eval/metrics.py`: `matches` → `matches_strict` → `grounded_refusal_correct`(근거 기준 거절 정확도의 정의).
3. `src/axbuilder/generation/refusal.py`의 `classify_refusal`: EXACT / PARAPHRASE / NONE. 좁힌 규칙이라 "확인이 어렵습니다 [1][2]" 같은 꼴은 NONE이다.
4. `src/axbuilder/generation/answer.py`의 `answer()`: 거절이면 글을 정해진 문구로 바꾸고 인용을 지운다. 그래서 "정해진 문구 + 정답"인 출력은 답이 사라지고, 놓친 거절은 인용이 달린 답으로 나간다.
5. 실험 기록 세 개 → ADR 0002·0006의 갱신 절 → ADR 0007.

## 면접 예상 질문과 답

**Q1. 44문항에서 유의하지 않던 리랭커 효과가 127문항에서 유의해진 이유는 뭔가요?**
효과가 커진 게 아니라 알아볼 수 있게 된 것입니다. 맥니마 검정은 한쪽만 맞힌 문항만 보는데, 44문항에서는 hybrid에서 그런 문항이 4개(4 대 0, 라벨 기준)라 p = 0.125였습니다. 127문항에서는 라벨 기준 10개(9 대 1, p = 0.021), 답 문구 기준 14개(12 대 2, p = 0.013)가 됐습니다. 쏠림의 비율은 비슷합니다. 실제로 같은 보고서에서 v0 44문항 부분만 떼면 지금도 5 대 1, p = 0.219로 유의하지 않습니다. 다만 비교를 여러 개 했기 때문에, 이 실험의 비교 11개를 한 묶음으로 Holm 보정하면 hybrid에 대한 결론은 남지 않고 BM25만 남는다는 것도 함께 말합니다.

**Q2. 답 문구 기준 채점은 왜 했나요?**
라벨 기준은 "근거 조항의 청크가 들어왔나"만 봐서 두 군데에서 후했습니다. 조항이 없는 상품설명서는 그 문서의 아무 청크나 정답이었고, 긴 조항을 나누면 답이 없는 조각도 같은 라벨이라 정답이 됐습니다. 그래서 근거마다 답이 든 짧은 원문 문구를 달고 그 문구가 든 청크만 맞게 셌습니다. 차이가 실제로 컸습니다. 문서 단위 근거 문항에서 라벨 기준 MRR이 0.20~0.24 높았고, 조항을 나눈 효과는 라벨로 보면 MRR이 오르고 답 문구로 보면 내려갔습니다. 반대로 dense의 리랭커 효과는 답 문구 기준으로만 유의했습니다. 그래서 두 기준을 늘 나란히 적습니다.

**Q3. 프롬프트 한 줄로 부정문 정답의 과잉 거절이 줄었는데 왜 채택하지 않았나요?**
한 지표로 보지 않았기 때문입니다. 부정문 과잉 거절은 판정기 기준 5~7 / 25에서 2 / 25로 줄었지만, 범위 밖 거절이 19 / 23에서 16·13 / 23으로 떨어지고 "근거 없이 답함"이 늘어 종합 지표는 그대로였습니다. 처음에는 "자료에 없는 질문에 답하게 됐다"고 해석했는데, 출력 원문을 읽어 보니 범위 밖에 지어낸 답은 하나도 없었고 판정기가 못 잡는 꼴의 거절이었습니다. 진짜 문제는 거절이 정해진 문구를 잃는 것이었습니다. 정해진 문구 거절이 절반으로 줄어, 제품이 거절을 알아보지 못하고 "확인할 수 없습니다"에 인용 다섯 개를 단 채 내보냅니다. 새로 답한 18건 중 3건은 틀린 답이었고, 문항 단위 순효과는 11 대 11이었습니다. 그래서 채택하지 않았고, 처음 해석이 틀렸다는 것도 기록에 남겼습니다.

**Q4. 여러 조합을 비교하면 어떤 문제가 생기나요?**
두 가지입니다. 첫째, 우연히 유의한 결과가 나올 확률이 커집니다. 이번에 k = 5 답 문구 기준으로만 문항 단위 비교를 16개 했습니다. 그래서 Holm 보정을 했고, 어디까지를 한 가족으로 보느냐에 따라 남는 결론이 달라진다는 것까지 적었습니다. 둘째, 가장 좋은 조합을 고르면 그 수치는 낙관적입니다. 같은 문항으로 고르고 같은 문항으로 평가했기 때문입니다. 실제로 답변 평가에 쓴 "가장 좋은 조합"도 표의 최고값은 아니었습니다(dense 쪽 MRR이 0.012 높았다). 대책은 질문을 미리 정하는 것(계획에 변수 하나씩 따로 보고), 보정, 그리고 새 문항이나 사람이 검수한 표본으로 다시 확인하는 것입니다.

**Q5. 상담원 역할에서 내부 문서가 새지 않는다는 건 어떻게 확인했나요?**
세 층으로 봤습니다. 검색 결과 상위 5개 750칸에 internal 문서 청크가 0개, 인용 190개 중 internal이 0개였습니다. 출력 글에는 내부 지침에만 있는 낱말(대외비, 소비자보호부, 문진표 등 10개)이 하나도 없었고, 같은 조건의 준법감시 실행에서는 8~10개 출력에 나와 이 검사가 실제로 잡을 수 있다는 것도 확인했습니다. 근거가 내부 지침뿐인 8문항 중 6문항은 거절로 판정되지 않았는데, 원문을 읽어 보니 "확인할 수 없다"는 거절 뒤에 공개 법령의 인접 정보를 덧붙인 것이었습니다. 누출은 아니지만 질문과 맞지 않는 공개 정보를 덧붙이는 것은 오해를 부를 수 있어 따로 적었습니다.
